## Intent
There are two ways to present a long page: **the page moves** (the page scrolls itself while the camera stays put — that's [evidence-scroll-tour](evidence-scroll-tour.md)) and **the camera moves** (the page lies still while the camera flies over it).
Only the latter is a "tour": what the audience sees is not a scrolling document but **a physical object lying on a stage, with someone pointing a lens at it spot by spot**.
The difference is the subject of the experience — the former is "the webpage demoing itself," the latter is "I'm walking you through it." Passages narrated live must use the latter.

There is only one key to getting it right, and it's the easiest to miss when porting: **each segment's zoom must pivot around the current point of interest**.
The method: compute the target point in pixels, set it as the `transform-origin`, then translate that point to frame center.
If you cheat with a fixed origin (center) + displacement, scaling pivots around the 2200px page's geometric center,
and the camera **flings out an unwanted lateral drift whenever zoom changes** — the read is "the camera hunting for something,"
not "the camera already knows where to look." This clause is the entire difference between this card and "enlarge a long image, then pan."

The second discipline: **holds must be genuinely still**. A tour's information lives in the holds, not in the moves;
the movement segments are merely the connective "we're going to the next spot." Leave no hold between segments and the audience finishes reading nothing.

## Motion Core
- Three structural layers: `.world` (`perspective: 900px` + `perspective-origin: 50% 42%`, mounted on the **parent container**) → `.camera` (camera layer, `preserve-3d`, the card's only transformed element) → `.page` (the long page itself, far taller than the frame)
- Base stage pose: `rotateX(14°)` + `rotateY(−20°)` + `scale(0.86)`. **The downward tilt is mandatory** — only with a downward tilt does a long page read as "lying on a stage"; pure `rotateY` reads as "a standing wall" (that's [tilt-3d-page](tilt-3d-page.md)'s semantics)
- Page geometry: width = frame width × 84%, height unrolling naturally with content (the demo is 806×2200). `top = (H − planeH)/2` is negative, so the page runs off frame top and bottom — **"taller than the frame" is this card's premise, not a side effect**
- Corner radius = 1.4% of frame width (960 frame → 13px), scaling with the frame
- Two ground layers (both belong to the stage; the camera flies while they stay put): the **contact shadow** = a 68%×11% flat ellipse + `blur(38px)`, the sole evidence of "sitting on the ground"; the **floor reflection** = `clip-path: polygon(7% 0, 93% 0, 78% 100%, 22% 100%)` (wide top, narrow bottom = ground receding) + `rotateX(58deg)` + `blur(26px)`
- **Point-of-interest addressing (the core technique)**: points of interest are given as normalized coordinates `(px, py)` (0–1, relative to page width/height), converted per frame to pixels `ox = px·planeW` / `oy = py·planeH`, then
  `transform-origin: ox oy` + `x = W/2 − (left + ox)` + `y = H/2 − (top + oy)`.
  Thus `scale` and `rotation` both pivot around this point, and the displacement carries it to frame center
- Keyframe path: each keyframe gives `{d, px, py, zoom, roll}` (d = segment duration). **Two adjacent keys with the same pose constitute a hold** — no separate hold mechanism needed; a repeated pose is the stop
- Segment easing fixed at `cubic-bezier(0.16, 1, 0.3, 1)` (the Apple curve): fast start, long-distance deceleration at the end ⇒ reads as "the camera already knows the target, goes there, and parks steadily." GSAP core lacks CustomEase; the demo self-solves the curve with 22 bisection steps (more accurate than approximating with `expo.out`)
- `roll` (body tilt, ±0.5–1°): only on the middle points of interest, and **in a different direction each segment**. Its job is to make each "docking" look like a handheld operator finding an angle rather than a mechanical slider indexing
- Entrance settle 0.8s (`power2.out` ≈ spring damping 26 / stiffness 90): `scale×0.94` / `rotateX +8°` / `rotateY −5°` / `y +64px` → into place; the two ground layers fade in simultaneously, following the displacement at 0.28 / 0.35 ratios (the nearer shadow moves more than the farther reflection)
- Handheld shake (optional tier): three sine waves at different frequencies (0.19 / 0.13 / 0.047 rad·frame⁻¹) stacked with smoothed noise, amplitude x≈7px / y≈5px / roll≈0.28°, tier 0.08–0.2. **The demo sets 0** — this is the low-frequency motion of "a camera operator's handheld breathing," not per-frame stop-motion jitter; enable only when a documentary roughness is wanted
- Exit: `zoom` pulls to 0.6 for the full view. **A long-page tour must close on the full view** — the audience has just seen three details and needs one glance at where they sit in the whole

## Parameters
| Parameter | Typical value | Tuning feel |
|---|---|---|
| `perspective` (parent container) | 900px (range 800–1100) | Spatial intensity. A long page spans deep, so go one notch nearer than a single-screen page ([tilt-3d-page](tilt-3d-page.md) uses 1000) for the "lying down" to read; <600px reads as fisheye distortion |
| `rotX` | 14° (range 10–18°) | Downward tilt. 0 = the long page reads as "a standing wall" and the card's semantics collapse; >22° the page compresses vertically too far and body-text line spacing looks like it's fighting |
| `rotY` | −20° (range 14–24°) | Side yaw. >30° the far end's body text becomes unreadable (a page meant to be read must never exceed this) |
| `scale` | 0.86 | Base scale, multiplied with each segment's `zoom`. The base sets "how far the whole sits back"; `zoom` sets "how close this spot gets" |
| `zoom` (point of interest) | 1.3–1.5 (full view 0.6–0.7) | Each spot's focal length. >1.8 the long page's side edges retreat into frame, exposing the stage floor (unless `px` is strictly 0.5); <1.2 doesn't read as "stopping to look at this spot" |
| `px` / `py` | 0.5 / 0.11–0.85 | Normalized point-of-interest coordinates. **The further `px` strays from 0.5 and the larger `zoom`, the likelier the stage beyond the page's side edges shows**; full-width sections always take 0.5, and only the "full view" pose deliberately shows the floor |
| Segment duration | 1.05–1.3s | The movement segments. <0.8s reads as "whipping past" (a transition's register); >1.8s the audience waits for it to arrive |
| Hold duration | 0.85–0.9s (production 0.8–1.2s) | The docking. **This is where the information actually gets read**; <0.6s the trip was wasted; in production size by "how many words this spot needs" |
| `roll` | ±0.5–1° | Body tilt. 0 = mechanical slider; >2° the audience thinks the frame is crooked (not "handheld" but "not held level") |
| Segment easing | `cubic-bezier(0.16,1,0.3,1)` | A fixed value; changing it is not advised. `power2.out`'s tail is too short and reads as "stopping abruptly"; `sine.inOut` starts too soft and reads as "drifting over" rather than "going over" |
| `entry` | 0.80s | The entrance settle. Don't start the tour before this segment ends (the demo covers it with a 0.9s opening hold) |
| `shake` | demo 0; production 0.08–0.2 | Handheld tier. >0.3 is no longer breathing but shaking |

## Known Pitfalls
- **`willChange: transform` on the camera layer** — with the camera layer continuously at fractional scale, the forced compositing layer makes the page's 1px border pulse between sharp and blurry (uglier than not promoting the layer). Correct: `will-change` only on **text containers** (`.sec` in the demo), stabilizing the glyph raster within each segment's scale; not on the camera layer, and not per character.
- Faking point-of-interest addressing with a fixed `transform-origin` (center) + displacement — zoom changes fling out a lateral drift, reading as "the camera hunting." This card's entire crux is setting the target point as the origin every frame.
- Large `zoom` + `px` off 0.5 — the long page's side edges retreat into frame, exposing the stage floor; the audience sees "the edge of a sheet of paper." Full-width sections always take `px` 0.5; to genuinely inspect left/right details, also pull `zoom` back within 1.2.
- No holds between segments (no repeated poses in the path table) — it becomes one continuous glide from top to bottom, which is [long-take-world](long-take-world.md) or [slow-pull-reveal](slow-pull-reveal.md), not a tour. **A tour's information lives in the holds.**
- Copying the original's floor-reflection parameters — remocn is a dark stage + bright purple reflection; copied onto white it reads as "two dirty gray wedges beside the page." On white, press the density below 0.05, narrow the width, and increase the blur.
- Not closing on the full view — after three details the audience doesn't know where they sit in the whole, and the tour reads as three unrelated close-ups.
- Points of interest ordered against the page's physical order (e.g. py 0.11 → 0.85 → 0.5) — the camera doubles back and the audience assumes they missed something. **Points of interest must be monotonic** (one pass, top-down or bottom-up).
- Forgetting `preserve-3d`, or writing `perspective` on the transformed element itself — the space falls apart (same pitfall as [tilt-3d-page](tilt-3d-page.md); details on that card).
- The long page not actually exceeding the frame (content only a screen and a half) — then no tour is needed; `tilt-3d-page` plus one slow push suffices. This card's cost only pays off on a long page.
- Handheld shake above 0.3 — from "operator breathing" to "shaky hands," and it conflicts with this library's signed-off "no boil / no stop-motion jitter" preference.

## Reuse Guide
- HTML/GSAP: `demos/stage-keyframe-tour/index.html`. Change the asset by replacing the DOM inside `.page` (or swapping in one full-bleed long screenshot `<img>`), setting `planeH` in the JS to the asset's true height; path and rhythm all live in the top-level `CONFIG.moves` (one keyframe per row `{d, px, py, zoom, roll}`; adjacent same poses = hold); stage pose in `CONFIG.rotX/rotY/scale`; handheld tier in `CONFIG.shake`. The liftable core: `CONFIG` + `bez()` + the `apply()` inside the `DemoShell.register` callback, plus the few lines of CSS for the three-layer structure.
- Minimal asset-swap procedure: (1) measure the long screenshot's native width and height, `planeH = 806 × (native height / native width)`; (2) each point of interest's `py` = that section's center pixel y in the long image ÷ native height; (3) `px` takes 0.5; (4) each segment's `d` sized by that line of the narration script, hold segments sized by "how many seconds this spot takes to read."
- Remotion port (this is the source): `registry/remocn/stage/index.tsx`. `resolveStagePose(frame, moves)` does keyframe interpolation (each key gives `{at, x, y, zoom, rotate, easing}`, default EXPO), `getStagePlaneGeometry` computes the plane geometry and `translateX/Y`, `getStageTransform` assembles the string, `getStageShake` produces the handheld shake (using Remotion's `random(seed)` rather than `Math.random`, guaranteeing per-frame determinism). Its `at` is an absolute frame number while this card's demo uses segment durations `d` — accumulate when porting.
- Long vertical travel (one segment spanning thousands of pixels): switch to remocn's smooth-descent three-phase scheme — 30 frames `in(cubic)` acceleration, a `linear` middle, 30 frames `out(cubic)` deceleration at the end. The arithmetic that makes it work: a 30-frame cubic ramp's displacement equals exactly 1/3 of a constant-speed segment of the same length, so the velocities join at both ends without a speed jump. A single EXPO over 2000px goes blur-fast through the middle.
- Editing-software equivalents: AE — put the long image in a 3D layer, add a Camera, keyframe the camera's `Position` / `Zoom`, **two identical keyframes per point of interest to form the hold**, `Easy Ease` the interpolation then shape the handles in the graph editor into "fast start, long end deceleration"; pivot-around-a-point zooming via the adjustment layer's Anchor Point, or by moving the camera rather than scaling the layer. CapCut — multi-segment "position + scale" keyframes with only a few fixed easing tiers, holds via two same-value keyframes; the perspective stage requires pre-baking the tilt into the image (CapCut's 3D can't do it live). Premiere — `Motion` Position/Scale keyframes + `Basic 3D`, holds likewise via same-value keyframes. **This is the asset marketplaces' "long page scroll showcase / website presentation" category**, but templates are usually "page scrolls" rather than "camera tours" — point-of-interest addressing you must build yourself.
- Sound: one light `whoosh` at each segment's start (`vol` 0.20–0.24, `dur` 0.55–0.75; the exit's whoosh with `rate` pressed to 0.86 = deeper and longer), one `lowpad` on the entrance. **Absolutely no sound during holds** — the stillness is their entire function.

## Scope
- Belongs to this card: **the multi-keyframe point-of-interest tour** as a whole — normalized point-of-interest addressing (target point set as `transform-origin` and translated to frame center, so zoom/roll pivot around the current point of interest), the "adjacent same poses = hold" path-table convention, the fixed segment easing `cubic-bezier(0.16,1,0.3,1)`, the ±0.5–1° `roll` alternating direction per segment, the 0.8s settle entrance (`scale×0.94` / `rotateX+8°` / `rotateY−5°` / `y+64`), the discipline of closing on the full view, the discipline that points of interest must be monotonic, the duration allocation of "holds carry the information, movement segments are only connective," the pitfall discipline of promoting `will-change` only on text containers and never the camera layer, and the taller-than-frame long page + perspective stage (the downward `rotateX` being the precondition for a long page reading as "lying down") + the two ground layers of contact shadow / floor reflection.
- Does not belong to this card: all content of the demo's grayscale wireframe landing page (nav / Hero / logo wall / three-column features / three big numbers / wide chart / three pricing cards / footer and their copy and layout), the specific "claim → data → pricing" ordering of points of interest, the specific count of three (3–4 both work; beyond 5 the audience can't retain them), the specific 14°/−20° stage-pose values, the specific handheld tier (demo 0), the two ground layers' specific densities and blur radii (tuned to the background), and any subtitles or highlight annotations layered over the page.
- Migration interface: `perspective` sets spatial intensity, scaling proportionally with frame width (this card designed at 960 wide / 806px page width); `planeH` back-computed from the asset's true aspect ratio; point-of-interest `py` = the section center's pixel y in the original ÷ original height, `px` = 0.5 for full-width sections; each segment's `zoom` validated by "is the smallest text at this spot readable in frame" (not by compositional taste); segment and hold durations sized line by line from the narration script (movement = the transitional phrase, hold = the sentence about that spot); `rotX`/`rotY` validated by "is the far end's smallest text readable"; the two ground layers' densities adjusted inversely to the background (lighter on white, bright-edged on dark).
- Background requirement: white works (demo-verified), but the two ground layers must be retuned for white (density pressed to the 0.05 tier, blur increased). A dark stage is the original context — there the reflection can use a bright gradient and the contact shadow can deepen, for a more "studio" look.
- Boundaries with this library's other camera cards: [slow-push-in](slow-push-in.md) / [slow-pull-reveal](slow-pull-reveal.md) are flat single-segment push/pulls; [tilt-3d-page](tilt-3d-page.md) is "the page standing up into a 3D facade" (single screen, no points of interest); [sway-parallax](sway-parallax.md) pans, [orbit-drift](orbit-drift.md) orbits with micro-drift — all **single motion + hold**; [long-take-world](long-take-world.md) is a world-coordinate 2D camera (no perspective plane, no point-of-interest addressing); [evidence-scroll-tour](evidence-scroll-tour.md) is the page scrolling itself while the camera stays put. **This card's differentiation is exactly three things**: the multi-keyframe path, the taller-than-frame long page, and normalized point-of-interest addressing. If the asset is a single screen, or one push-in suffices, use the cards above — don't pay this one's cost.
