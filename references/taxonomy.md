入场永远比出场更用力；同屏重音同一时刻只能有一个。

## 字幕花字

> **底部字幕素排铁律（2026-08-27 用户定版）**：最下面那条跟读字幕**不加任何动效**——
> 整句硬现、素排。唯一例外是 keyword-pop-highlight，且同一个视频内**最多出现 3 次**，
> 除非用户明确要求更多。本类其余各卡的作用对象都是**标题/金句/要点等独立文字层**，不是底部字幕。

### keyword-pop-highlight ✅已完成（格式基准）
关键词弹出强调 · P0 · 通用；**唯一允许作用于底部字幕的动效，≤3 次/片**。见 references/cards/keyword-pop-highlight.md。

### typewriter-reveal
打字机档案戳 · P1
- 一句话：等宽字体逐字符敲出地点/日期戳（MOSCOW, 1962），末尾方块光标 500ms 闪烁，档案感
- seen_in: Johnny Harris, LEMMiNO, Fireship(代码版), James Jani
- spec：字符逐个出现 30~80ms/字符（速度略随机 ±20ms 更像真打字）；方块光标 █ 跟随，句尾以 500ms 周期闪 2~3 次；配合深色档案底（暗纹理/暗角）；第二行副信息延迟 0.4s 再敲。demo 场景：画面角落敲出 "北京 · 2008年8月" 式的时间地点戳 + 一行小注。
- pitfalls：匀速出字像 CSS 教程；无光标不像打字机；字符间距跳动（必须等宽或 ch 单位）
- tech：JS 定时切片 + GSAP 控制节奏；Remotion 按 frame 取 substring

### quote-card
金句大字卡 · P1
- 一句话：说到金句时人物让位，整屏深色底多行大字自上而下逐行弹出，关键词换色放大，停留后整卡退场
- seen_in: 张琦/参哥类商业口播, 罗翔(黑屏白字版), 何同学(白底黑字版), 抖音大字报片型
- spec：入场：底色板 0.25s 淡入盖住人物（人物压暗或缩角）；3~5 行大字逐行错峰 120~180ms 弹入（y 30px→0 + opacity，power3.out）；行内 1~2 个关键词用高亮色且字号 1.2x；hold 2~4s（demo 2s）；出场整卡 0.3s 下滑淡出回到人物。罗翔变体：纯黑底白字居中逐行淡入，无任何装饰。demo 演大字报版为主。
- pitfalls：行行都弹得很花＝廉价感，行内不要再加字级动画；金句超过 5 行就不是金句；底板透明度不够文字和人物打架
- tech：GSAP timeline stagger；Remotion 逐行 spring + Sequence

### soft-blur-in ◇
柔焦淡入 · P1 · 本类**最低能量**的一张，唯一可以连着上五句都不闹。见 references/cards/soft-blur-in.md。
- 一句话：一句话像被镜头对焦出来——整块文字从 blur 9px 起、边解糊边淡入走满 0.9s，12px 下沉位移只占前 0.3s，逐字错峰仅 1 帧（0.033s）留下一道几乎读不出的左→右扫过感
- 定位：本类其余各张都在"打点"（弹出、砸重音、敲字），共同代价是**都在争注意力**；本卡的字不是"出现"的而是**被对焦出来**的，观感是"画面本来就有这句话，只是刚刚看清"。因此它能用在字很多、字很频繁的地方（旁白句、结论句、切素材后第一句），也因此它不能承担任何强调职责
- 命门：**解糊与淡入走满 0.9s、位移只占前 33%**（同停就读作"整块被推上来"，位移先停之后那 0.6s 只在解糊才是"对焦"）；**错峰只有 1 帧**（放到 0.1s 以上就变成另一张卡"逐字柔焦"，能量档跳整级）；模糊量恒为**字号的 1/6**（比例常量，换字号必须等比）
- pitfalls：把 `filter: blur()` 加在整行而不是单字（整行成一个合成层，逐字错峰全失效、中文行糊成一条灰带）；位移与解糊用两条不同缓动（慢放下看得出字先停住再单独解糊）；底有细密纹理（字在 0.9s 里始终是半透明糊块，底上细节透过来就读不出字）

### per-character-rise ◇
逐字升起 · P1 · 有方向、有力道、零回弹的整句立起。见 references/cards/per-character-rise.md。
- 一句话：每个汉字从自己位置下方 24px 升到位，位移 0.33s、淡入 0.70s **走两条不同缓动**，逐字错峰仅 1 帧——整句读作"一股气顶上来"而不是一个个蹦，全程零模糊零缩放
- 定位：市面"上滑淡入"预设九成是位移与淡入同曲线同时结束，做出来没有骨头（一块半透明板子被推上来）。本卡的差别全在两条参数上：两条缓动分开（位移近匀速到位＝"到位"是硬的，淡入长尾缓收＝"实起来"是软的）+ **位移只占淡入的 48%**（力道在前、余韵在后）
- 命门：两条缓动**必须不同**（共用一条无论哪条都让"到位"和"实起来"变成一件事）；**零模糊零缩放**是硬约束（加 blur 就退化成 soft-blur-in，加 scale 就退化成弹跳字幕）；起始下沉恒为**字号的 44%**
- pitfalls：错峰放到 0.1s 以上用在中文长句（中文字宽整齐，均匀大错峰读作一道正弦波浪，一眼廉价）；用在连续跟读的常规字幕（每句都从下往上升，整片读作画面在往上抖）

### line-by-line-slide ◇
逐行滑入 · P1 · 本类唯一的**多行要点**卡（不带底板）。见 references/cards/line-by-line-slide.md。
- 一句话：3~4 行要点一行一行从左侧 36px 外滑进来（位移 0.47s / 淡入 0.90s，行间错峰 0.13s），读完整叠再从同一侧往右**穿出去**
- 定位：「三件事」这类并列要点有个专属难题——整段是一个整体但要一行一行讲。三行一起淡入读不出顺序，三段各自入场又割裂成三张卡；本卡的解法是**一叠里的错峰**（0.13s 大到能读出先后、小到三行入场大幅交叠）
- 命门：**进从左、出向右不是倒放**（整叠"穿过画面"才接得上下一段；退回去读作"这段作废了"）；**出场横向位移比淡出迟 0.267s 才起**（前 0.27s 整叠只在原地变淡、然后才被抽走——同起读作"被一把扫掉"，观众觉得没读完，这条延迟是本卡签名）；**出场错峰只有入场的一半**（出场不必再讲一遍顺序）；**左对齐**是硬要求（共享左端才成"一叠"）
- pitfalls：行数放到 5 行以上（首行已淡出、末行还在入场，"一叠"读不出且读不完）；中文照抄源码 `lineHeight 1.1`（相邻行粘住，滑入时上下行的字互相压——中文取 1.35）；出场缓动照抄入场的缓出（"甩走"变成"缓缓飘走"，收不干净）
- 与 quote-card 的分界是**要不要让位**：金句要仪式感（底板 + 人物压暗）用那张，要点"边讲边挂在旁边"用本卡

### tracking-in ◇
字距收拢 · P1 · 本类唯一的**标题动作**（不是字幕）。见 references/cards/tracking-in.md。
- 一句话：一行大标题的字距从 0.5em 极松收拢到 −0.03em，**同一条 spring** 同时把 9px 模糊解开——散开的字一边聚拢一边聚焦成一块，起手 0.3s 走掉 80%、剩下 0.5s 极慢地咬到位，全程零回弹
- 定位：字幕的动作要短、要跟语速、要能连着上；标题的动作可以长、可以只做一次、可以让整屏为它停下来。`chapter-title-card` 是带色块压屏的"卡"、`quote-card` 是多行金句 + 底板，两张都自带整套画面结构；本卡只有**一行字**落在现有画面上。机制是唯一的：**字距**（横向、对称、从两端往中间，与本库任何字幕卡的运动方向都不重合）
- 命门：字距与模糊**必须由同一条 spring 驱动**（分成两条缓动，慢放下能看出字先咬到位再单独解糊，那就是两个动作）；spring 是**零回弹的长缓收**（damping 18 / stiffness 90，ζ=0.949，过冲仅 8e-5——最后那段极慢的咬合是全部"贵气"来源）；**淡入不跟 spring**（独立 0.5s 线性，只有 spring 的一半——字显形时字距已收掉九成，观众看到的是结果的最后一段而不是全过程）
- pitfalls：`letter-spacing` 用 px（或交给 GSAP 自动 tween，它会换算成 px）——换字号后收拢幅度不再等比；换成有回弹的缓动（字距过冲到负值、中文字互相压那一帧极难看）；用于多行文本（每行各自收拢、宽度变化不同步，整块读作在呼吸）；当常规字幕连续用（1.0s 跟不上语速，一片限 1~2 次，用多了"贵气"就贱了）

### slab-punch-title ◈
重点放大 · P0 · 本批标题色块类的基准式，"铺垫 + 结论"对照句专用。见 references/cards/slab-punch-title.md。
- 一句话：两行标题里第二行的重点词坐在斜切色块上——第一行整块硬现 0.18s，色块从中心 scaleX 撑开 0.22s，**块撑到位那一帧**白字才硬切出现并从 1.12 倍 punch 落定（5 帧）
- 命门：块先到位、字后落（反了读作"字被块追上"）；斜切是静态属性不是动效

### speed-slab-title ◈
速度块标题 · P1 · 同类里唯一带**速度语义**的一张。见 references/cards/speed-slab-title.md。
- 一句话：主标题硬现后副题的斜切色块从画外 180px 冲入到位（0.28s power4.out），到位那一帧块左缘一次性张开三道长度不等的速度线（42/30/22px，错峰 2 帧）随后 0.2s 内淡尽，块内的字用 40px 反向补偿被裁一截读作"字比块慢半拍在追"
- 命门：速度线是**冲入的残影**，必须 0.2s 内消失——留在屏上就成装饰

### impact-open-title ◈
冲击开场 · P0 · 开头 3 秒钩子，全片限 1~2 次。见 references/cards/impact-open-title.md。
- 一句话：整句一次砸出（scale 1.08→1，0.2s power4.out），末词延后 3 帧单独换强调色再 punch；四角 L 取景框同帧起但走 0.3s 更慢地向内收 12px，点阵网格最后错峰淡入 0.4s 且只到 0.5 不透明度，副题收尾上浮
- 命门：一屏只砸一次——角框与点阵是**衬**，必须比标题更慢更淡，抢了就散

### alt-block-lines ◈
双色块对句 · P1 · 同类唯一的**双行对照**块式标题。见 references/cards/alt-block-lines.md。
- 一句话：两行对句各坐在自己的贴合色块上、错峰 0.12s，每行色块从左 scaleX 展开 0.26s，文字用 clip-path 右侧收 100%→0 同曲线同时长**滞后 2 帧**被块的右缘"刷"出来；对句关系靠同结构反色表达
- 命门：文字必须被块刷出来（clip 跟随），块和字各自淡入就是两个动效不是一个

### outline-box-title ◈
描边框标题 · P1 · 给结论加框，机器画的框（对照 hand-drawn-ellipse◈ 的手绘线）。见 references/cards/outline-box-title.md。
- 一句话：圆角描边框沿路径**一笔画完一圈**（0.42s 近匀速，精确闭合不过头），框闭合后实心 chip 从左 scaleX 展开 0.2s、chip 内白字滞后淡入，最后三枚 chevron 依次点亮
- 命门：框是"框选"不是"手绘圈"——匀速 inOut + 精确闭合，两种语言别混

### count-badge-title ◈
数字重音标题 · P1 · 开场承诺条数（"三个方法"）。见 references/cards/count-badge-title.md。
- 一句话：数字「3」先单独从 1.6 倍缩到位并在落定那刻换成强调色，紧接着「个方法」被它从右缘 clip 推出来，第二行错峰 0.1s 淡入上浮，收尾数字再补一记 5 帧 punch
- 命门：数字是主语，必须**先到且单独到**——三段同时淡入就没有"几个"这个重音

### quote-bracket-pull ◈
引号夹句 · P1 · 不盖底板的金句卡（人物全程在画面里）。见 references/cards/quote-bracket-pull.md。
- 一句话：两枚压过正文三倍的大引号从画外对角**同帧**向内推入把一片空白夹成"引文区"，引号走过一半时三行金句才开始错峰 0.09s 淡入上浮，末行关键短语最后被荧光笔扫过 0.26s

## 强调标注

### highlighter-sweep
荧光笔高亮扫过 · P0
- 一句话：引用文段上半透明黄色荧光笔从左到右扫过关键句，同时其余文字压暗 30~50%，读者视线被押着走
- seen_in: Vox, Johnny Harris, Cleo Abram, James Jani
- spec：文章/引用截图卡片先在屏（可静置或轻微 Ken Burns）；荧光色块（#FFE949 60% 透明度，mix-blend-mode:multiply）从关键句左端向右 scaleX 0→1 扫过，0.4~0.8s 匹配朗读语速，transform-origin left；同帧其余段落 opacity 降到 0.5~0.7；扫完关键句整句轻微放大 1.03 浮起。色块边缘可用 border-radius 不规则值模拟笔触。demo：一段 4~5 行的引用文字，第 3 行被扫亮。
- pitfalls：色块盖住文字（必须 multiply 或半透明）；扫太快像 bug；不压暗其余文字=强调失效；色块四角太规整像表格选中
- tech：CSS mix-blend-mode + GSAP scaleX；Remotion 同理，宽度 interpolate

### scribble-annotation
手绘圈注箭头 · P0
- 一句话：马克笔质感的圈/下划线/箭头按真实笔顺现场画出，画完保持干净静置
- seen_in: Ali Abdaal, Johnny Harris, Vox, Mrwhosetheboss, LottieFiles arrow/underline 品类
- spec：SVG path + stroke-dasharray 描画：下划线一笔 0.3~0.6s；椭圆圈 0.4~0.6s 两段（起笔快收笔缓，power2.inOut）；箭头先杆后头两笔共 0.5s。线条粗细 4~8px、圆头 linecap、颜色红/黄/白；画完保持静置（本库定版：不做 line boil / 定格抖动）。demo：一张假截图上依次演圈、下划线、箭头三种。
- pitfalls：匀速描画像 loading；线太细没有笔感；圈画得太圆像椭圆工具
- tech：GSAP DrawSVG 思路（原生 dashoffset 即可）；Remotion 用 evolvePath(@remotion/paths)

### magnifier-detail
局部放大镜 · P1
- 一句话：截图某处浮出一个圆形放大镜（1.5~2 倍，白描边+投影），0.3s 从原位弹出到空白区，本体同步压暗
- seen_in: 笔吧评测室等评测类, 差评君, 剪映标准教程
- spec：底层假截图；放大镜 = 圆形容器内放同一截图的放大副本（background-size 放大 + 背景定位对准目标点，或复制 DOM 元素 scale）；入场从目标点 scale 0.3→1 + 位移到旁边空白区 0.3s power3.out，白描边 3~4px + 大投影；同时底图 brightness 降到 0.6，目标点处可留一个细描边框 + 连接线连到放大镜。hold 期间放大镜内容轻微平移扫视。
- pitfalls：放大内容和原图对不上位（校准 background-position）；放大镜盖住目标本体（必须弹到空白区）；无连接线时读者找不到出处
- tech：CSS background 双图技巧 + GSAP；Remotion 同理，用同图两个 <Img> 加 clipPath

### callout-line-label
标注引出线 · P1
- 一句话：目标上圆点 pop 亮起 → 折线向外生长 → 线端文字标签遮罩揭示，三拍一气呵成
- seen_in: Johnny Harris, Vox, Call-Out Titles(4.5K销量), 产品评测
- spec：三段时序：圆点 scale 0→1 约 0.2s（back.out）+ 一圈涟漪扩散；折线（1~2 个拐点）stroke 描画 0.3~0.5s power2.out；标签文字容器 clip-path 从线端方向展开 0.25s，文字略微滞后 0.1s 淡入。退场反向收线。demo：一台假手机/产品图上两个 callout 先后标注（第二个延迟 0.8s），演示多标注错峰。
- pitfalls：三段同时开始就没有"引导视线"的因果感；折线斜率随意显得乱（拐点用 45°/水平）；标签先于线出现是最常见错序
- tech：SVG line dashoffset + GSAP timeline 串接；Remotion Sequence 三段

### strike-and-replace ◇
划线纠错替换 · P1 · 本类唯一能表达"否定"的一张。见 references/cards/strike-and-replace.md。
- 一句话：一条语义色横线 0→100% 划穿旧值，划完那一刻旧值淡出、新值从同一位置下方 8px 升起顶上来——替换感来自"占了同一个位置"，句子其余部分零位移
- 定位：本类其余六张全是"**加强**"（砸重音/涂高亮/放大/压暗/引线/圈注），能让一个词变重但没有一张能表达否定；而"不是 A，而是 B"是口播极高频句式（旧观念/旧价格/上一代参数/传言）——**划穿的动作本身就是论证**
- spec：三段按总时长比例切（`total` 是唯一时长旋钮）——划线 0→40%（`scaleX 0→1`，`origin: left`，`power1.inOut`）→ 交换 40~60%（旧值 opacity 1→0；新值 opacity 0→1 + `y +8→0`，**同位**）→ hold 60~100% 让观众读完这条论证
- 命门：新旧值绝对定位**同位叠放**（换行另起或旁边并列都读作"这里有两个数据"）；**语义色只上那条线**，文字保持墨色（给新值也上色就把"旧值被否掉"这一拍抢轻了）；容器宽度先用 `visibility:hidden` 的隐形尺子撑住（取 from/to 里更长的那串）
- pitfalls：划线动 `width` 而不是 `scaleX`（每帧重排，在 inline-block 槽里还带着整句抖）

### ink-underline ◇
墨迹下划线 · P1 · 本类唯一有**笔压**的一条线，作用在句子里的一个词上。见 references/cards/ink-underline.md。
- 一句话：一条起笔压满、收笔提细的墨色缎带沿关键词下方 0.4~0.5s 生长出来——变宽不是描边粗细而是路径自己的两条边算出来的，笔尖走过那一刻的宽度就是它的终宽，画完静置
- 定位：本类已有两种"给字加记号"——`highlighter-sweep` 是荧光笔色块（强调"这一整句"，靠面积压视线）、`scribble-annotation` 是圈注箭头（作用对象是素材而不是文字）。本卡是第三种：比荧光笔**轻**（不占面积、不改字底色，一句话里能连划两个词而画面不脏），比圈注**准**（线的两端就是词的两端，读作"就这两个字"）。最常用的语境是**对比式论述**——先给错的说法划一条、再给对的划一条，两条线的存在本身就把"不是这个、是那个"讲完了
- spec：脊线是一条三次贝塞尔 40 点采样，两控制点上下**反向**偏 ±1px 成一个极浅 S 弯（两条线的 `wobble` 取反号，避免并置时弯法一致读作程序批量生成）；缎带半宽 `pressure 1 → release 0.15`（起笔压满纸、收笔提到 15%）；线心落在 `measureText` 量出的**真实 baseline** + 6px（照行盒画线会飘在句子外面一截）
- 命门：**变宽靠路径不靠描边**（`stroke-width` 是常数，画不出笔压——必须沿脊线逐点求法线、按 taper 撑出半宽、左岸正走右岸倒走闭合成填充路径）；**截断脊线而不是 dashoffset**，且 **taper 的 t 按整条脊线算**（按已画部分归一化会让每帧笔尖都最细、落定又变粗，读作会膨胀的橡皮筋）；**画完静置**（源码原版是 5 个定格姿态 + 逐格重新哈希抖动，正撞本库"不做沸腾"——手作感全部交给形状）
- pitfalls：用 `stroke-dasharray` 描这个填充路径（dash 会沿缎带**轮廓**跑一圈，像一根线在绕圈）；`grain` 照搬源码 1.0（10px 的线上位移 5px，收笔那 1.5px 的细端被咬断成几点墨）；一句话里划 3 个以上的词（同屏重音只能有一个，上限 2 条）；线宽给到 16px 以上（读作荧光笔，那是 highlighter-sweep 的地盘）

### hand-drawn-ellipse ◈
手绘圈重点 · P0 · 指认单个短语，比双线强、比爆点字克制。见 references/cards/hand-drawn-ellipse.md。
- 一句话：一笔逆时针画出的歪椭圆圈住关键短语——0.5s 画到 1.08 圈让尾巴过头 8% 与起笔交叉，圈画完之后短语才 punch 1.06→1 一拍，然后静置 1.8s
- 命门：**必须过头交叉**（闭合成完美椭圆一眼是矢量图形）；圈画完才 punch，同时发生就乱
- pitfalls：圈整句（圈的语义是"就这几个字"，圈一整行读作框选）；与 scribble-annotation 的分界是作用对象——那张画在素材上，本卡圈句子里的短语

### converging-arrows ◈
双箭头聚焦 · P1 · 本类指向性最强的一张（箭头有方向，圈没有）。见 references/cards/converging-arrows.md。
- 一句话：两支手绘箭头从对角空白处几乎同时画向关键词（错峰仅 0.06s，杆 0.26s + 头 0.11s，箭尖停在离词 16px 处不戳字），两支箭尖都到位那一帧关键词才 punch 1.18→1 并换成强调色，箭头留在屏上 hold 1.6s
- 命门：箭头**先到、词后炸**；箭尖要留白 14~18px 不许戳到字上
- pitfalls：同屏有多个候选词（双箭头只能夹一个目标）

### corner-bracket-frame ◈
对角角框 · P1 · 定题用的取景动作（"本集只讲这一件事"）。见 references/cards/corner-bracket-frame.md。
- 一句话：左上与右下两个 L 形角框**同帧**从各自的外侧对角方向平移 20px 进入，框先立住 0.22s 后标题两行错峰 0.1s 淡入上浮，最后一道浅弧线在标题下 0.22s 划出
- 命门：只画两个**对角**的 L（四个角是"取景框"是另一种语言）；两臂长度要相等、两框必须同帧
- pitfalls：用在需要砸重音的爆点句（本卡是克制的取景感，不是重音）

### quote-hold-arrow ◈
金句停留 · P1 · 本类唯一强调**整句而不是词**的一张。见 references/cards/quote-hold-arrow.md。
- 一句话：三行金句先全部以普通样式错峰淡入、末行原地平淡地停 0.34s，然后才**升级**——黄色高亮框从末行文字中心 scaleX 铺开 0.24s、框到位后文字 punch 一下，然后停住（2026-08-26 用户定版去掉了原来第三拍伸出的箭头：它把视线从句子引开，还占掉末行右侧 104px 版面）
- 命门：末行必须"**先平淡、后升级**"两拍——一上来就高亮就少了"重点在这一句"的推进感
- pitfalls：用在一上屏就要砸的钩子句（那没有铺垫可升级）

### number-counter
数字滚动计数 · P0
- 一句话：大号数字从 0（或乱数）滚到目标值，1~1.5s 先快后慢，落定瞬间轻放大一拍，单位随后淡入
- seen_in: 小Lin说, 何同学, Wendover, 影视飓风, Odometer 模板(1.2K销量)
- spec：两种模式都演：a) tween 版——数值 0→目标 easeOut 1~1.5s，千分位逗号实时格式化，落定瞬间 scale 1→1.08→1 一拍 + 单位/涨跌箭头淡入；b) odometer 版——每位数字竖向滚轮，高位先停低位后停（stagger 由高到低收敛）。深色底大字（120px+），旁边配小字说明。demo 演 "¥3,000,000,000" 类量级。
- pitfalls：线性滚动无落定感；小数位一起乱滚读不出量级（先定整数位）；滚太久（>2s）观众已经听完这句话了
- tech：GSAP snap+onUpdate 或逐位 yPercent；Remotion interpolate + Math.floor

### chart-grow
图表生长 · P0
- 一句话：坐标轴先淡入，柱子从 0 依次弹性长出、柱顶数字跟着弹出；折线沿路径描画、数据点逐个亮起
- seen_in: 小Lin说(signature), 回形针, Vox, Wendover, Infographics Mega Bundle(2.2K销量)
- spec：轴+网格线 0.3s 淡入 → 柱状：每根 scaleY 0→1（origin bottom）0.5s power3.out、stagger 100~150ms，柱顶数值标签在该柱到顶时 pop；关键柱用高亮色其余灰调 → 折线变体：path dashoffset 描画 1~1.5s，数据点沿途 scale pop，末端数值计数。demo 演 5 根柱的对比图，最后一根（最高）高亮红色并触发一次轻 punch。
- pitfalls：所有柱同时长出=没有"逐项列举"的语感；y 轴乱缩放柱子对比失真；标签和柱不同步像贴上去的
- tech：div/SVG + GSAP stagger；Remotion spring 每柱 + delay=i*4 帧

### info-term-card
名词解释悬浮卡 · P1
- 一句话：说到专业名词时，圆角信息卡（图标+词条+两行释义）从人物空侧滑入，停留期间缓慢上下浮动像悬浮着
- seen_in: 小Lin说(signature), IC实验室, 财经知识区, FCPX/剪映同款预设商品
- spec：卡片 = 浅色渐变底 + 投影 + 左侧圆形图标 + 词条名粗体 + 1~2 行小字释义；入场从人物对侧屏外滑入 0.35s power3.out + 3% 过冲；落位后 y 方向 ±6px 正弦浮动（周期 2.5~3s）营造"悬浮"；图标可微转；出场原路滑出 0.25s。demo：主持人占位右侧弹出"「量化宽松」QE：央行印钱买债券"式卡片。
- pitfalls：浮动幅度大了像漂走；卡片压住人脸；释义超过两行观众读不完；无投影贴在背景上没有"悬"感
- tech：GSAP 入场 + repeat:-1 yoyo 浮动；Remotion 浮动用 Math.sin(frame/fps*2π/T)

### map-route-pin
地图路线图钉 · P1
- 一句话：地图上虚线从 A 城生长到 B 城，到达瞬间图钉从上方砸下带一次压扁回弹，地名标签侧滑而出
- seen_in: Johnny Harris, Wendover, LEMMiNO, Half as Interesting
- spec：底图用内联 SVG 画风格化地图（暗底 + 描边国界/海岸线抽象形状即可，不要真地图数据）；路线 = 贝塞尔虚线 dashoffset 生长 0.8~1.5s（可带小飞机 emoji 沿 path 移动）；图钉 y -60px→0 落下 0.25s power2.in，落地 squash（scaleY 0.7 + scaleX 1.3 一帧）回弹；地名标签 0.2s 从钉侧滑出；起点钉先亮。demo 演两地一线 + 第三地延迟接入，模拟"从北京到上海，再到深圳"。
- pitfalls：路线匀速直线像 PPT 连接线（要弧线+缓动）；图钉无 squash 落地轻飘飘；多条路线同时长出失去叙事顺序
- tech：SVG path + GSAP motionPath 思路（原生 getPointAtLength）；Remotion evolvePath + spring

### step-timeline-vertical ◈
竖向步骤线 · P1 · 有先后依赖的流程（顺序不能颠倒）。见 references/cards/step-timeline-vertical.md。
- 一句话：一条竖线从上往下 0.6s 画下去，线推到哪个位置那个圆节点就弹出来、2 帧后右侧两行字跟着左移淡入（三个节点每 0.18s 一个，由解线缓动的反函数算出）；三组全部到位后第一个节点升级成强调色空心环并放大 1.25 倍标出"你现在在这一步"
- 命门：节点必须**跟着线的推进**出现（线到哪、点亮哪）——线画完再统一弹点就丢了"时间轴"语义
- pitfalls：用于并列清单（那用 numbered-step-stack◈）

### numbered-step-stack ◈
编号步骤堆入 · P1 · 并列清单式干货（没有线，是"堆叠"不是"推进"）。见 references/cards/numbered-step-stack.md。
- 一句话：四枚带编号方块的横条从右侧以严格均匀的 0.11s 错峰依次堆进来，每枚落定的同一帧它的编号块 punch 一下（1.12→1，4 帧）当"落地确认"，四枚都到位后整组轻微上浮 4px 把它们收成一件事
- 命门：错峰必须**均匀**（不均匀读作卡顿）；编号块的 punch 是"落地确认"不是弹跳
- pitfalls：用于有先后依赖的流程（那用 step-timeline-vertical◈）

### metric-with-sparkline ◈
数字带趋势 · P0 · "一个数 + 它怎么来的"双层信息。见 references/cards/metric-with-sparkline.md。
- 一句话：小标签先淡入，大数字 0→67 滚 0.9s，下方小折线在同一刻起跑用 0.6s 画完、四个数据点跟着线端依次弹出；数字停住那一帧「%」和上箭头才出现——结论比过程晚半拍
- 命门：滚动结束前不出现单位与箭头（数字还在动就有结论＝假）；折线与计数**同时**启动不是先后
- pitfalls：只报一个孤立数字时用它（那用 number-slab-pop◈）

### bar-chart-growth ◈
柱状增长 · P0 · 讲连续区间的趋势"整体形状"（不是逐项对比）。见 references/cards/bar-chart-growth.md。
- 一句话：标题淡入后基线从左画出 0.24s 立好地面，七根柱以 0.06s 的密错峰从基线一路升起（读作一次连续动作而不是七个动效），最后一根到顶那一帧结论 chip 在柱顶留白里弹出
- 命门：错峰要**密**（0.06s，一串而不是七个动效）；柱子只用 scaleY（改 height 每帧重排）；最高柱要留顶部余量给 chip
- 与 chart-grow 的分界是**语义**：那张 stagger 100~150ms 是"逐项列举/对比"，本卡密错峰是"一路涨上来"的整体形状

### number-slab-pop ◈
数字弹出 · P0 · 一次弹出的**结论感**数字（钩子数/封面数）。见 references/cards/number-slab-pop.md。
- 一句话：实色块先从上方落定 0.24s（数字此刻还不在场），块稳住后巨大整数一次弹出 scale 0.72→1（back.out 1.7），小数与单位延后 6 帧单独淡入，说明行最后淡入上浮 6px
- 命门：块和数字**不能同时进**（同时进读作一个整块 PNG）；整数先立住、小数是精度补充；数字用 tabular-nums
- 与 number-counter / metric-with-sparkline◈ 的分界是**过程还是结论**：要展示"怎么算出来的"用滚动计数那两张，一句话就要立住用本卡

## 素材呈现

### media-pop-in
素材弹入堆叠 · P0
- 一句话：截图/照片带白边和投影从 80% 弹到 100% 带回弹，歪 5~10°，多张错峰 100~150ms 依次拍上来堆叠
- seen_in: Fireship, Ali Abdaal, Johnny Harris, 差评君, 剪映入场动画
- spec：每张素材：scale 0.8→1.02→1（back.out(1.7) 手感）0.25~0.35s + opacity 0→1 前半程完成；随机 ±5~10° 旋转错落；白描边 6~10px + 投影；多张 stagger 100~150ms、位置错开堆叠（后来者压前者一角）；全部落位后整组轻微呼吸（可选）。退场 0.15s 缩小消失。demo：主持人讲话时右侧连拍三张"证据截图"（用 CSS 画的假截图）。
- pitfalls：不旋转不堆叠=PPT 排版；每张都正中央轮播失去"甩证据"的密度感；入场 >0.4s 拖节奏
- tech：GSAP stagger；Remotion 每张一个 spring + delay

### news-card-desk
新闻卡片划重点 · P0
- 一句话：新闻截图包成白色圆角卡片从下滑入，红色下划线 0.3s 扫过标题关键句，卡片全程缓慢 Ken Burns
- seen_in: 小Lin说, 差评君(伪窗口版), IC实验室, 评论向频道
- spec：卡片（白底圆角 + 假新闻排版：报头/标题/正文灰条）从画面下方 y 60px→0 滑入 + 淡入 0.4s power3.out；落位即开始极缓 Ken Burns（scale 1→1.04 全程 8s 线性）；1s 后红线在标题关键词下 scaleX 0→1 扫出 0.3s（origin left），可再叠一个红框 draw-on 圈数字；第二张卡片 1.5s 后从右侧滑入叠在前卡之上（stagger 堆叠）。
- pitfalls：Ken Burns 快了像镜头晃；红线和朗读不同步；卡片直挺挺立在中央（要轻微歪 1~2° 更像"摆上桌"）
- tech：GSAP timeline；Remotion interpolate 慢推 + Sequence 红线

### terminal-typing-log ◇
终端逐行推进 · P1 · 拿命令行当证据。见 references/cards/terminal-typing-log.md。
- 一句话：终端窗里命令逐字符敲出、日志成 4 字一簇地"蹦"出来，写满 8 行后缓冲区整跳一个行高（零插值），以 `...` 结尾的行打完自动冻结 0.6s 制造悬念，末尾成功行是全片唯一的语义色
- 定位：讲"我真的跑过这个东西"时静态终端截图说服力接近零（看不出是跑出来的还是拼出来的），而"文字慢慢出现"的伪终端更糟（读作网页加载动画）。价值全在三条**手感纪律**上，做对了观众不用读懂日志也会相信"这段是真跑出来的"
- spec：**① 分块突进**——`revealed = min(len, ceil(linear/chunk) × chunk)`，日志 `chunk 4` @68 char/s（成簇蹦出）、命令 `chunk 1` @23 char/s（人在敲键盘），两条速率差一个量级就是"人"和"机器"的区别；**② 滚动零插值**——`translateY = −溢出行数 × 行高`，该行开打那一帧整跳，没有 tween；**③ 省略号悬停**——`...` 结尾的行打完冻结 0.6s，这 0.6s 里画面完全静止（光标已撤）。可见 8 行是硬约束，未到时刻的行用 `visibility:hidden` 占位不重排
- pitfalls：逐字符匀速（一眼 CSS 教程）；滚动加 ease（立刻读作"网页在滚"）；语义色给多行（日志/命令/报错都上色就成彩虹终端，"成功"那一拍的重量没了）；用于非技术受众（终端本身会筛掉观众）

### chat-message-flow ◇
聊天记录自演 · P0 · 把截图证据从过去式改成现在进行时。见 references/cards/chat-message-flow.md。
- 一句话：我方消息先在底部输入框逐字打出、停 0.33s 后弹上屏，对方先出"正在输入"三点气泡（时长按回复长度算）再弹消息，反应表情在消息落定 0.27s 后贴上；整张时刻表由文本长度自动生成
- 定位：聊天截图是口播里出现频率最高的证据素材，但截图只能被"拍上台"（media-pop-in），它永远是**过去式**；本卡把同一份记录变成**现在进行时**，且每条消息的出现时刻天然对齐你的讲述——你念到哪句，那句正好上屏
- spec：`buildSchedule()` 一遍算完所有时刻点（我方 `typeDur = clamp(字数 × 0.12s, 0.6, 2.6)`、对方 `thinkDur = clamp(字数 × 0.115s, 1.1, 2.3)`，中文按字符数）；我方链路＝输入框逐字揭示 → 停 `sendGap 0.33s` → 发送与上屏同帧（发送键 `scale 1→0.84→1` 按压反馈、光标打字中实心不闪、停手才 2Hz 闪）；对方链路＝三点气泡淡入 → 一直跳（相位差 = 周期/6，波从左往右推）→ 上屏前 0.2s 淡出；气泡弹入 0.47s（`y 12→0` + `scale 0.94→1`，origin 在自己那侧下沿），**行占位比弹入早 0.07s**（先顶后落）
- pitfalls：缺了前戏（退化成"气泡依次淡入"——两条链路各有自己的前戏才是本卡）；手数帧的时刻表（换文案全废，且必然出现"两个字的消息打了两秒"）；做成微信绿/iMessage 蓝（观众开始读平台品牌，且你要为仿真背锅——必须灰阶中性皮）；用来展示大量历史消息（自演只演 2~4 条）

### logo-enter ◇
Logo 登场 · P1 · 本类唯一的**身份标识**入场（其余都是证据素材）。见 references/cards/logo-enter.md。
- 一句话：品牌圆牌用 spring 从 0.5 倍弹到位（唯一带过冲的一拍），错峰 0.233s 后字标从圆牌一侧推出、副行再错峰一拍，同时一圈描线绕着圆牌合拢——三拍收尾，落定即终帧
- 定位：收尾是全片最容易做俗的一拍（logo 旋转飞入、光晕扫过、粒子炸开——观众看过一万次，且都在抢戏；片尾的职责是"落幕"不是"再来一个高潮"）。本卡把 remocn 那套克制的 spring 手感搬过来，编排成口播片的标准收尾三拍：**圆牌 → 字标 → 描环合拢**
- 命门：**只有第一拍有过冲**（圆牌是唯一带弹性的元素，`back.out(1.1)` ≈ 4%；给字也加弹跳两个弹性元素互相抢，收尾就变成了开场）；**拍距 0.233s**（同时发生读作一张贴图淡入，>0.5s 读作三件无关的事）；**落定即终帧、不加 idle 微动**（这是全库少数明确**不要**呼吸/漂移的地方——片尾的"停住"正是它要的效果）
- pitfalls：描环用匀速（读作 loading 进度圈）或比字标先落定（收口的线先没了，三拍的收束感散掉——它必须最后落定）；`dasharray` 恰等于周长（首尾在起笔点留一道亚像素白缝，1080p 下一眼可见——给周长 + 3px）；白底上照搬源码的白环 + `rgba(0,0,0,0.5)` 重投影（环消失、投影糊成脏斑）；一片里用 3 次以上（读作水印）
- 与 media-pop-in / motion-blur-slam-in◆ 的分工：那两张是**证据素材**入场（要歪、要叠、要密，"啪啪啪甩上来"），本卡是**身份标识**入场（要正、要单、要停住，"这是谁"）。两者过冲量差一倍不是巧合——甩证据要 10%，立品牌只要 4%

### chat-gpt ◇
ChatGPT 对话框 · P1 · AI 聊天产品自演（**单行药丸 + 首屏三件套**那一路）。见 references/cards/chat-gpt.md。
- 一句话：首屏三件套按阅读顺序错峰淡入（问候大标题 → 药丸输入条 → 建议 chips，位移带视差），提示词逐字打进单行药丸、圆形语音键**原地变形成圆形发送键**且 chips 同时淡出下移，发送后问候语退场让位给对话，回答分块流式吐出
- 定位：这套界面语法的五个特征——单行药丸而不是宽卡（一次一句话）、建议 chips 摆在输入条下面（首屏在教你能问什么）、问候语占据画面正中（对话开始才让位）、morph 是**圆 → 圆**（形态不变只换图标与底色）、点睛色在**语音**端而不是发送端。做产品对比视频时这些形态特征**就是内容本身**
- 命门：**三段错峰的位移视差**（源码给标题 ×0.4、药丸/chips ×0.6 两个不同乘数——远的元素动得少；拉平了就是"整块一起飘上来"的模板感）；**chips 随 morph 退场而不是随发送退场**（"手一落键，建议就不需要了"是这个产品的因果，等发送才退就慢了半拍）；**chips 一去不回**（跟的是**不回退**的 morph 正向进度——否则发送键退回语音态时 chips 会跟着回来，读作"首屏又回来了"）；**问候语活到发送那一帧**（打字期间它还在，那是"首屏还没提交"的唯一证据）
- spec：**产品皮 = 内容本身**（2026-08-25 用户定版：完全还原 ChatGPT 的样式——`#0D0D0D` 墨字 / `#E3E3E3` 药丸描边 / `#F4F4F4` 用户气泡 / `#2F6FED` 语音键 / 助手位那朵 OpenAI 结，照抄源码 `THEMES.light`；灰阶化之后它退成"某个聊天框"，单行药丸/chips/问候语/圆→圆 morph/点睛色在语音端这五条产品取向全部读不出来）
- pitfalls：把 ChatGPT 的皮灰阶化或助手位换成几何圆占位（产品身份读不出来，这张卡的存在理由就没了）；morph 做成圆 → 方（那是宽卡 composer 类产品的形态，改了就丢掉这个产品的形态特征）；点睛色给发送端（这个产品的 accent 在语音端）；建议 chips 摆四枚以上（首屏变成菜单，观众开始读 chips——三枚是这个形态的容量）；提示词超出单行（药丸 `nowrap` 会挤出去，长提示词不适合这个形态）

### claude-code ◇
编码智能体终端 · P1 · 演**因果链**而不是 stdout 流水。见 references/cards/claude-code.md。
- 一句话：深底终端窗弹入后三段错峰按阅读顺序铺开（欢迎框 → What's new 栏 → 提示行），命令逐字符敲进提示行、回车后整行退成灰，接着「工具调用 → 结果 → diff → 结论」的因果链逐行分块蹦出，工具调用行的状态点在出结果前一直呼吸，diff 的 `+` 行是全窗唯一语义色
- 定位：`terminal-typing-log◇` 解决的是通用终端当证据（命令 → 日志 → 结论的 stdout **流水**）；但 coding agent 的终端不是流水而是**因果链**——每一步都得看清"它调了什么工具、返回了什么、于是改了哪一行"，这条链是 AI 编程内容的全部信息量。观众要判断的不是"它跑没跑"，是"它到底干了什么、干得对不对"
- spec：**产品皮 = 内容本身**（2026-08-25 用户定版：完全还原 Claude Code 的样式——陶土橙 `#D97757` 的虚线框与骑边标题与 What's new 小标与吉祥物、深底 `#1B1A18` / 窗饰条 `#3A3633`、macOS 三灯真色、源码那枚像素兽，照抄源码 `THEMES.dark`；灰阶化之后它是"某个终端"，"我真的让这个工具干过这个"的指向性就没了。陶土橙是**身份色**、不参与"改了什么"那套四级分级，与唯一语义色 `+` 行的绿不冲突）；工具调用行带**状态点且出结果前一直 1.1Hz 呼吸**（"它在干活"这一拍，只改亮度）、结果行带 `⎿` 折角缩进（因果关系靠缩进表达）、diff 两行只隔 0.14s（同一次编辑的两半）、`+` 行是唯一语义色
- 命门：**三段错峰顺序 = 阅读顺序**（框 → 右栏 → 提示行，落点正是接下来要打字的地方；乱序或同时淡入就丢掉"界面在铺开"）；**行间延迟不等距**（工具调用前等得久＝它在想调什么，diff 两行几乎连着，结论前再顿一下——全表等距一眼是假数据）；**语义色只给 `+` 行与 `✓`**（del 行用灰不用红，两色对上就成彩虹 diff，"改了什么"反而看不清）；命令 `chunk 1` @11 字/s 与日志 `chunk 3` @54 char/s **差一个量级**（这就是"人在敲"与"机器在吐"的区别）
- pitfalls：把 Claude Code 的皮灰阶化、或吉祥物换成方块几何占位（像素兽是这个工具首屏最强的识别物）；提交后命令行不退灰（命令与日志同亮，读不出哪个是输入哪个是输出）或提示行光标不撤（两个光标同时闪，一眼是 bug）；行光标打完不撤（七行闪成圣诞树，且行间停顿段画面不再静止）；未到时刻的行用 `display: none`（每出一行整段重排一次，读作"每出一行抖一下"——用 `visibility: hidden` 占位）；结论行放在中间（会被后续日志冲下去）；日志写十几行完整 agent trace（终端是**证据**不是内容，6~8 行一条链足够）
- 两张 AI 产品卡的分工：讲"我和 AI 聊天/提示词技巧"用 chat-gpt◇，讲"AI 帮我写代码"用本卡；两张一起上就是"聊天型 + 终端型"的完整证据链。**vs ui-flow-theater◇**：那张演的是**人操作界面**（光标走位 + 控件状态机），本卡演的是**界面自己在生成内容**（没有光标、没有点击，全部动作来自智能体）

### glass-code-walk ◇
玻璃代码走读 · P1 · 带观众读一小段真实代码（**同时只有一行是亮的**）。见 references/cards/glass-code-walk.md。
- 一句话：玻璃质感代码块弹入、10 行代码逐行落位，相机推到 1.68x 后按「读一行 → 滑到下一行」逐句走读（浮点行号同时驱动相机与高亮带），非当前行压暗到 0.30，读完 0.85s 拉回全景解除压暗
- 定位：口播讲代码有两个死角——贴一整屏，观众眼睛不知道落在哪儿（你念到第 5 行他还在读第 1 行）；只贴关键两行，看不出它们在什么结构里。本卡的解法是**代码整块都在，但同一时刻只有一行是亮的**：视线被高亮带牵着走、节奏由你定，周围行压暗但没消失、结构感一直在。玻璃块本身是**手段不是目的**（半透明深底让语法色成立，backdrop blur 让块内块外能看出同一片背景的两种状态）。**视觉按 remocn 源码原样实现**（2026-08-25 用户定版：`rgba(10,10,10,0.6)` + `blur(16px)` 玻璃、1px 渐变描边、macOS 三灯真色、五个源码 `TOKEN_COLORS`、暗调照片背景），连示例代码都用源码的 `DEFAULT_CODE`
- 命门：**浮点行号 `linePosition` 同时驱动相机与高亮带**（同源 ⇒ 只有一条时间轴，两者不可能失步；带子在行间**滑过去**——一格一格跳的高亮是"程序在切 class"，滑过去的才是"眼睛在移动"；给带子单独排 tween 去追相机，任何时长改动都会错开）；**停顿式而不是匀速**（每行停 `dwell 0.32s` 再滑 `stepDur 0.26s`——匀速传送带读作"代码在自动播放"，观众会等它播完而不是听你讲）；**收全景**（拉回 `zoom=1` 同时**解除压暗**，从"读这一行"回到"读整体结构"，不收这一拍等于没讲完）；压暗是**连续量** `1 − |i − linePosition|`（二值切换会让"滑动"退化成"闪"）
- pitfalls：`transform-origin` 用默认 `center`（反解公式失效，错得"像 bug 但说不清哪儿不对"——必须 `0 0`）；纯反解不加边界钳制（首行/末行时画幅被推出块外，白底舞台上就是大片空白——源码深底看不出，移植必补）；块宽小于走读焦距下的可视宽（`960/zoom`，横向钳制退化为居中、画幅两侧常年露白边）；行用 `display: flex`（丢掉纯空白匿名子项，token 间空格与缩进全消失，`export function` → `exportfunction`）；走读停在空行上（`stops` 要过滤空行，但插值仍连续经过它）；块宽收窄了却照抄源码字号（最长行的行尾被切在块外——**字号与块宽是硬耦合**，按 `可用文本宽 ÷ (最长行字符数 × 0.6)` 复算，本卡 600px 块取 17px）；拿它读 30 行代码（>12 行改用 evidence-scroll-tour◆）
- 与 cursor-locked-zoom◇ 的分界（同源机制的另一档）：两张共享同一条反解公式与"镜头由内容进度驱动"的纪律，但档位不同——那张是 2.6~2.8x **deep-zoom 跟光标**（锁 x 到字符、目标在逐字符移动），本卡是 1.5~1.8x **逐行走读**（锁 x 到块心、整行完整可读、目标在逐行移动）。念一条长命令用那张，读一段多行代码用本张

### gooey-morph ◇
图块拼入 · P1 · 素材呈现类里的"并列拼"（另两张是"歪着叠"与"同向怼"）。见 references/cards/gooey-morph.md。
- 一句话：n 张图各自走 L 形路径从画外飞来——先横向滑到自己的列、再纵向落进行位，起飞时刻故意不按左右顺序，几张图几乎相接地拼成一条横排，拼完即落点
- 沿革：2026-08-26 用户定版，**只保留原「粘液融字」的前半部分**。去掉的后半段是 goo 三段管线（高斯糊 → alpha 阈值收紧 → 湍流位移）融化成字——那套管线的用途是"色块换形成字"，而现在方块本身就是要看清的内容（图），把图糊掉再收紧只会读作渲染坏了。于是本卡从「字幕花字」挪进「素材呈现」
- 命门：**L 形路径**（x 走前半程、y 走后半程，拐点在缓动进度 0.5）——两轴同时走就是斜线飞入，那是最普通的 fly-in；**起飞时刻不按左右顺序**（0/0.13/0.27/0.43s，第 2 张最先到）——按顺序依次到位读作程序在循环刷 DOM；缓动 `cubic-bezier(0.88,0.14,0.12,0.86)` 的**陡中段**是"被吸到位"的手感
- spec：`count` 是唯一的张数入口（3~6），单张宽以 `picW` 为上限、整条装不下时按图区可用宽自动等比收窄，所以改张数不会有任何一张被 `overflow` 切掉；张间缝 ≤8px（小缝才读作"拼成一条"）；入场一律从**背着人物那一侧**进场
- pitfalls：改 `count` 却手动写死 `picW`（整条撑破图区、末张被无声切掉）；`entryFrom` 给了朝向人物的方向（图横穿人物身上且被切）；张间缝给到 20~40px（变成几张各自摆着）；给图加旋转（那是 media-pop-in 的"歪着叠"语义，本卡的全部意义是并列整齐）
- 与同类三张的分工：`media-pop-in` **歪着叠**（各带旋转、层层压住，"一沓照片拍上桌"）/ `motion-blur-slam-in◆` **同向怼**（方向模糊高速甩入急停，"怼到你脸前"）/ 本卡 **并列拼**（严丝合缝一条横排，"这是一组，它们并列"）。三者不在同一段口播里混用

### 界面剧场子类（整套界面按脚本自演）

2026-08-26 用户定版：原来这是第 8 个独立类别，现并入本类作为子类——它的同源卡（terminal-typing-log / chat-gpt / claude-code / glass-code-walk / cursor-actor-demo）本来就都在素材呈现里，单卡成类没有意义。下面这套「共有纪律」仍然成立，是所有「界面自己在演」的卡共用的。

产品/工具类口播讲"这个东西怎么用""AI 现在在干什么"时，常见三条路都有硬伤：录屏（光标 12px 看不见、
节奏由手速决定、要脱敏就废了）、截图硬切（丢掉"这一步导致了那一步"的因果）、逐个控件各做动效
（每个控件一条时间线，排到第三个就对不上拍了）。这类卡是第四条路：**把整套界面当一个演员，给它一份剧本**
——界面按脚本时间轴自演，观众看到的是"这一下导致了那一变"的因果链，而制作者只维护一张表。
与本类其余各张的区别在于素材的时态：那些是把已发生的证据**拍上台**（过去式），本子类是让界面**当场演**（现在进行时）；
与「运镜」的区别在于动的是谁：运镜里动的只有相机、界面本身一个像素不改，本子类里相机不动、界面自己换态。

共有纪律（本子类通用）：
- **时间只从一处进入**：一张时刻表（`STEPS` / `FRAGMENTS` / 轮数）是唯一的时间源，
  光标、控件、结果都是它的函数。对齐靠共享常量，不靠两处手数——这是能排到三拍以上还不散架的全部原因。
- **换态是硬切，不是动画**：界面状态变化要一帧到位（`transition: none`）或极短（0.27s 一档全卡共用）。
  给状态变化配过渡就变成"样式在做动画"，观众读不出是哪一下触发的。
- **时刻表按内容长度自动累加**，改文案不用重排时间；各动作时长是**手感常量**（不跟着语速缩放——
  语速快时该减少拍数，而不是加快每一拍）。
- **灰阶中性皮 + 唯一语义色**：控件全部灰阶线框，语义色只留给收尾那一拍（成功 toast / 品牌红那一行）。
  做成某个真实产品的配色，观众开始读平台品牌，且你要为仿真背锅。

### ui-flow-theater ◇
界面流程剧场 · P0 · 界面剧场子类的架构母卡，讲完整流程。见 references/cards/ui-flow-theater.md。
- 一句话：整套灰阶假设置面板按一条 STEPS 时刻表自演一遍完整流程——光标走位（路点弧线 + 按压涟漪）与控件换态（开关滑、分段切、滑杆拖、按钮转成功）共享同一批 `at` 常量同拍发生，最后一记成功 toast 滑入收尾
- spec：**STEPS 时刻表是骨架**——`[{at, target, act, move, until}]`，`at` 是这一拍**按下**的时刻，`act` 是 `click`/`drag`（`until` 只有拖拽拍才有）；约 **1s/拍**（一拍一个口播短句）；入场两级揭示（整卡 blur 0.6s → 区块每 0.2s 错峰，全部落定后光标才起步）；光标语言（x/y 分缓动成弧线、跨区 0.62s / 相邻 0.40s、到位悬停 0.2s、按压 0.09s 锚在箭头尖 + 涟漪 0.35s、**换态发生在按下中点不等抬手**）；四种控件响应共用一个 0.27s 换态时长；toast 三段（滑入 0.47s + 停 1.8s + 退 0.47s）
- 命门三条：**时间只从一处进入**（`at` 是唯一时间源，光标与控件都读它）、**坐标是命名常量**（控件落点运行时用 `P(el, fx, fy)` 反算成 `POS.xxx`，光标路点只引用名字，换布局不用改数字）、**一个控件一种响应**（每个控件一个响应函数，函数内部没有时间参数）
- 与 cursor-actor-demo◆ 的边界（重要）：那张是**光标单动作语法**（一枚光标怎么移动/悬停/按压/拖，一个动作对一个口播词），控件响应只是用来证明"点了有反应"；本卡是**整套界面按脚本联动的架构**，光标降级成时刻表的一个消费者。只演一两个动作（"你就点这里"）用 cursor-actor-demo；要演一条完整流程（三拍以上、多控件、有收尾回执）用本卡。两卡光标是同一份代码，**升级光标造型时两边同步改**
- pitfalls：语速变化时缩放各动作时长（`moveLong`/`hoverHold`/`press`/`swap`/`toastIn` 是手感常量，跟着语速缩放会让快语速下的操作糊成一团）

## 转场结构

### chapter-title-card
章节标题卡 · P0
- 一句话：段落切换时全屏色块压入，大号章节编号（01/02）先落位，章节名随后滑入，停 1~2 秒切回口播
- seen_in: 差评君, 小Lin说, LEMMiNO, Johnny Harris, IC实验室
- spec：色块（品牌色或深色）从一侧 0.3s 扫入盖屏（power4.inOut）→ 超大编号（衬线或超粗体，屏高 40%）scale 1.3→1 + 淡入 0.4s → 章节名从编号旁遮罩揭示（clip-path inset 侧向展开）0.35s，小字英文/日期戳延迟 0.1s 淡入 → hold 1.2s（元素带极缓漂移防呆滞）→ 反向或直切出。demo 连演两个章节卡（01 → 02）示意节奏。
- pitfalls：编号和标题同时出=层次塌掉；hold 期间完全静止像卡帧；转场比内容还长（全程勿超 2.5s）
- tech：GSAP timeline；Remotion Sequence + interpolate

### shape-wipe-transition
色块扫屏转场 · P0
- 一句话：两三层色块以 50~80ms 错峰从同一方向扫过全屏，最后一层扫走时画面已换成下一场景
- seen_in: 所有 YouTuber pack(15~140个/包), BASE(2.5K销量), 影视飓风, 综艺化口播
- spec：3 层色块（同色系深中浅）依次 x -100%→100%（或斜切 skew -12° 的矩形）各 0.45s power4.inOut、层间 delay 60~80ms；第二层过屏中线的那一帧把底下内容 A 换成 B（观众看不见切换瞬间）；色块可带轻微拉伸变形（速度感）。demo：场景 A（主持人）→ 扫屏 → 场景 B（数据图表占位）。
- pitfalls：单层色块=幕布拉过；层间错峰超过 120ms 会看见缝隙露馅；内容切换时机不在遮挡帧内穿帮
- tech：GSAP timeline + 中点回调换内容；Remotion 同帧判断切 Sequence

### caret-wipe-transition ◇
光标擦除转场 · P1 · 本库第一个**边界本身有语义**的转场。见 references/cards/caret-wipe-transition.md。
- 一句话：一条 3px 文本光标从左到右扫过 1.33s 完成换场——走过之处露出新场景（沉降解糊，像刚被打出来），未到之处仍是旧场景（上浮失焦，像正被退格吃掉），互补裁切永不露缝
- 定位：运动承接六式全是**相机动量交接**（边界线本身没有含义）、shape-wipe 的色块是**不透明遮挡物**（职责就是让你看不见换场那一帧）；本卡那条竖线不是遮挡物而是一个文本光标，同一次擦除同时说了"刚被打出来"和"正被退格吃掉"两件事。讲"我把这段重写了""AI 把它改成了这样"时编辑器的隐喻自己把因果讲完了
- spec：**一个进度量驱动三件事**——`x` 0→100（`cubic-bezier(0.65,0,0.35,1)`，1.33s），每帧写新场景 `clipPath: inset(0 (100−x)% 0 0)` / 旧场景 `inset(0 0 0 x%)` / 光标 `translateX(x% × 画幅宽)`
- 命门：**互补裁切**（两层共用同一个 x，差半个百分点就在边界露一条底色缝）；**两侧微反差是灵魂**（新场景 `y +3→0` + `blur 2→0`；旧场景 `y 0→−6` 匀速上浮 + `blur 0→4` 起手延后 10%——去掉就退化成普通硬边 wipe，那已是 shape-wipe 的地盘）；**白底不加发光**（原版的 `box-shadow: 0 0 18px` 是深底+荧光绿的语言，搬到白底只会糊出脏边，改实色细条）
- pitfalls：用于真人出镜之间的切换（光标隐喻与人像无关）

### chapter-progress-list ◈
章节进度 · P1 · 本类唯一带**进度信息**的转场（讲到哪了、还剩几段）。见 references/cards/chapter-progress-list.md。
- 一句话：暗场里四条章节从右侧错峰 0.1s 滑进来，全部站定后**只有当前那一条**换成强调色、左边弹出一枚圆点、整行再往前一步，同帧四角电影角框向内收 10px 淡入把这一幕封住
- 命门：高亮只有一条；未激活行靠 **dim 实色**区分，不许叠透明度；本卡是全库少数允许深底的一张（章节转场的语义是"幕间暗场"，白底读不出"这是转场"）
- pitfalls：只有两段的短口播用它（两条列表撑不起一次转场）；与 chapter-title-card 的分界是**要不要给全局位置**——单幕开场用那张，要让观众知道进度用本卡

### behind-text-title
人后大字视差 · P1
- 一句话：大标题从人物身后升起，字在人身后被遮挡穿出，人物与文字轻微反向漂移形成伪 3D 层次
- seen_in: 影视飓风(signature), 何同学, vlog 化知识区
- spec：三层：背景 → 大字标题层 → 前景人物（demo 用 CSS 剪影占位）；标题入场：y 40px→0 + 淡入 + 字距 0.2em→0.05em 收拢 0.5~0.6s power3.out，字的下缘被人物剪影遮住；hold 期间标题与人物做反向极缓漂移（各 ±4px，8s 周期）维持层次感；标题字号要大（屏高 25%+）且与人物有 20% 以上重叠面积才读得出"在身后"。

### subscribe-cta
多平台关注 CTA · P1
- 一句话：控件弹入 → 光标弧线移入交互 → 状态翻转 + 确认动效；三种平台式样（YouTube 订阅 / B站一键三连 / 通用关注）共用这一套机制，单式样 3s 内完成
- seen_in: 几乎所有 YouTube 口播频道, B站三连引导, 小红书/抖音关注贴纸, Like Subscribe Bell Overlay(1.7K销量), LottieFiles subscribe 品类
- spec：共有三段——控件 scale 0→1.06→1 弹入 0.35s → 光标从屏外弧线移入 0.8s（x power2.inOut / y sine.inOut）→ 交互帧下压 0.94 一拍 + 按下即翻转状态 + back.out(3) 回弹 + 光标滑出。三式的确认动效各不同：**A YouTube**＝变灰"已订阅" + 铃铛 rotate ±16° 衰减摇摆 0.8s + 一圈涟漪；**B B站三连**＝长按进度环 0.55s 走满 → 三个灰阶线框图标（拇指/圆币/星星）从左到右 0.2s 间隔依次点亮（换高亮底 + scale 1.22 弹跳 + 逐个涟漪）；**C 通用关注**＝黑胶囊变灰"已关注" + 对勾 dasharray 划入 0.36s。段落淡出淡入 0.3s，用完即走。可配"啵/叮/嗒"音效位（demo 无声）。

### x-follow-card ◇
关注卡弹出 · P1 · 介绍**别人**的社会证明道具。见 references/cards/x-follow-card.md。
- 一句话：X 资料卡整体 spring 弹入（0.62s 微过冲），十层内容随后按阅读顺序 0.07s 错峰 **blur-in** 逐层落位，光标弧线移入点击"关注"，同帧三件事一起发生——按钮两态交叉翻转 + 胶囊涟漪 + **粉丝数纸带上推 +1**
- 定位：口播说"这个人做的东西你该看看"，观众心里的问题是"他是谁、凭什么"，一张资料卡一次答完。但本卡的价值不在"贴一张卡"，在于**卡自己演一遍被关注的过程**——光标走过去点下关注、按钮翻成已关注、粉丝数当场 +1。这一下把静态资料变成社会证明：不是你在夸他，是"有人正在关注他"
- 命门：**壳与内容分两拍**（卡整体先弹入到位、十层内容**再**逐层落；十层同时全亮＝一张图淡入，那就只是贴图）；**光标必须走过去**（瞬移点击读作"状态自己变了"不是"有人关注了他"，社会证明的说服力归零）；**点击那一刻三件事同帧**（前两件是"这一下按到了"，**计数变化**才是社会证明的落点——少了它这次点击只影响了一个按钮、没影响任何事实）
- spec：**产品皮 = 内容本身**（2026-08-25 用户定版：完全还原 X 的样式——深色卡 `#16181c` / 品牌蓝 `#1d9bf0` 的封面渐变与认证印章与关注按钮 / 右上 X 标，照抄源码 `THEMES.dark`；灰阶化之后那张卡"不是任何平台"，社会证明的出处就断了）；光标落点要在按钮**终态**位置上量并减掉箭头尖偏移（否则点击帧压在按钮下方的空处——2026-08-25 实修的 bug，验收要**截点击那一帧**）；十层 blur-in 是 `blur 8→0` + `opacity` + `y 8→0` **三属性同动**（只做淡入是普通 stagger，加上 blur 才有"从虚焦里对上焦"的落位感）；层序按阅读顺序且**按钮行排最后**（待交互的目标最后落位，光标才有东西可点）；内容铺完后留 0.34s 静置给口播介绍这个人；粉丝数 +1 用**纸带上推**（窗口固定 `overflow:hidden` 只露一行高、纸带在里面推——动窗口会把整行文字一起挪；直接换值读作"数据刷新了"）
- pitfalls：两态用改 `textContent` 实现（读作"字变了"不是"按钮换了状态"——两层叠着交叉、退的缩进的涨）；计数增幅小到看不见（`128,431 → 128,432` 那一位观众看不见，等于没滚）；`fromTo` 忘了 `immediateRender: false`（涟漪环建表时就刷上 from 态，"还没被点"时环已挂在按钮外圈）；卡的 `transform-origin` 用默认 center（整卡上下同时长大，读作弹窗不是卡片落位——锚在卡顶）；把 X 的皮灰阶化（观众读不出这是哪儿的账号，社会证明的出处就没了——这类卡产品皮属于内容）；只跑 verify 的 t0/t1 两帧就算验收过（那两帧大概率不在点击时刻上，光标没点到按钮会一路漏过去）；光标常驻不走；同一张卡出现两次（第二次观众直接跳过）
- 与 subscribe-cta 的分工：那张是**语法合集**（三种平台式样串演、落地只留一段），目标是"**示范观众去点**"，用在**收尾的价值兑现点**，overlay 只有控件没有卡；本卡是**单卡精做的社会证明道具**（十层内容 + 一次关注交互 + 计数变化），目标是"**证明这个人值得看**"，用在**介绍嘉宾/账号的时刻**。两张共享"控件弹入 → 光标弧线移入 → 点击反馈链 → 状态翻转"这套机制，差别是**卡还是控件**、**证明还是号召**、**中段还是收尾**；同一条视频里可以都出现，但不要挨着放。**vs lower-third-nameplate**：那张是"这个人是谁"的最小信息（自己出镜报身份），本卡是"这个人凭什么"的完整档案 + 一次交互

### chevron-lower-third ◈
动态人名条 · P1 · 比 lower-third-nameplate 多一档"节目感"。见 references/cards/chevron-lower-third.md。
- 一句话：姓名行从左推出（x −26→0，0.26s），职称 chip 错峰 0.1s 从左 scaleX 展开 0.22s、chip 内字滞后 2 帧淡入，三枚 chevron 再依次扫过点亮当"条子还在延伸"的收尾；hold 2.0s 后整条从左收回
- 命门：区别全在 **chip 展开 + chevron 收尾**这两处（正式访谈与纪录片仍用更克制的 lower-third-nameplate）
- pitfalls：hold 太短（人名条要停够，观众得读完）

### danmu-bubble-praise ◈
弹幕气泡 · P1 · "评论区都在说"的社区共识道具。见 references/cards/danmu-bubble-praise.md。
- 一句话：四枚评论气泡按 0.55s 错峰从最近的边缘外侧飘入，每枚只停 0.75s 就上移 18px 淡出——进出交叠到第 3 枚进场时第 1 枚正在走，四枚里只有一枚是强调色
- 命门：必须**交叠进出**（全进全出读作"一组标签"不是弹幕）；只有一枚带强调色，其余走灰阶
- 与 x-follow-card◇ 的分工：那张是"这个人凭什么"的完整档案，本卡是"很多人都这么说"的即时共识

## 运镜

静态素材（网页截图/图片/文档/UI 界面）一贴上屏画面就死——观众没有理由把眼睛留在上面。
前七张卡不改素材一个像素，只让**相机**动（末一张 pip-zoom-box◈ 是例外，见下）：素材满画幅铺在一个"相机层"里，相机层是唯一被 transform 的元素。
选型：**默认用 slow-push-in**（任何静态素材的底噪运镜）；素材信息量大且要揭示规模用 slow-pull-reveal；
把页面当"产品/作品"展示用 tilt-3d-page；素材比画幅宽得多用 sway-parallax；
页面要在屏上停留很久（长讲述）用 orbit-drift；素材超出画幅且要"讲到哪儿镜头停到哪儿"用 stage-keyframe-tour◇；
目标本身在移动（光标/进度点/正被填的字段）用 cursor-locked-zoom◇；
要在保留全景的同时长期展示一个局部用 pip-zoom-box◈（唯一不动整幅画幅的一张）。
**一段素材只用一式**——推着又摇着读作手抖。
2D 两式（推/拉）与 3D 三式可以串联：tilt-3d-page 建立立面姿态 → orbit-drift 接管 hold 期底噪是推荐组合。
前五张都是**单段运动 + hold**（一段一个姿态目标），后两张◇是**多目标寻址**：一个走预设兴趣点路径、
一个锁运行时才知道位置的移动目标——这是"单段运镜"与"路径/跟拍"的分界。

共有纪律（前五张通用，也是与其他类别最大的差别）：
- **相机永不静止**：hold 期必须以主段末速继续走。前五张卡的 ease 都是"末速非零"的自定义曲线
  `p + (1−r)·p²·(1−p)`（起速=平均速、末速=r×平均速），**不能用 `power2.out`**——它末速为零，到位那帧镜头停死。
  例外有两处：tilt-3d-page 的立起段是一次"摆放"动作（有始有终的事件），允许收住；
  **stage-keyframe-tour◇ 与 cursor-locked-zoom◇ 整条反过来**——它们的 hold 必须**真的静止**
  （巡游的信息量在 hold 里、跟拍要留时间让人读完），静止在那两张卡里是功能而不是失误。
- **时长跟着口播走，运动量不跟**：`zoomTo`/`ampRot` 这些是观感常量（换时长不改），时长才是节奏变量。
- **可读性是硬上限**：3D 倾斜 ≤25°（超过远端正文读不了）、摇移 ≤190px/s@960 宽（超过观众扫读跟不上）、
  推进 ≤1.2（超过位图发虚）。3D 卡的透视值 900~1200px——太小读作鱼眼变形，不是空间。
- **3D 三式的投影必须跟着姿态变**：与页面同处 `preserve-3d` 空间（被透视自动压扁）+ 浓度随倾斜加深
  + 位置往倾斜反侧偏移。投影不动 = 页面读作贴纸而不是浮在空间里的实体。
- 素材分辨率 ≥ 画幅 × 最大缩放（1080p 画幅推到 1.15 需 ≥2210px 宽的截图），否则运镜即变糊。

### slow-push-in
缓推特写 · P0 · 静态页面的默认底噪运镜。见 references/cards/slow-push-in.md。
- 一句话：scale 1→1.08~1.15 匀速推进 8~15s，transform-origin 咬在兴趣点上、画幅同时微移把它让向构图位
- spec：相机层唯一被 transform；origin 咬兴趣点（运行时读包围盒反推，全程恒定——origin 一变画面会跳）；主推匀速或 `camEase(0.6)`；叠 5~15px 焦点微移；hold 期沿末速匀速续推 3~5%
- pitfalls：用 power2.out（末速为零停死 + 前段读作"冲"）；推过 1.2 位图发虚；推完就停；拿它当入场动效；同一段既推又拉
- tech：一条 `interpolate`（`Easing.linear` 或末速非零的 bezier）+ `transformOrigin` 百分比；剪映/AE 的 **Ken Burns 推镜半边**，关键帧必设线性

### slow-pull-reveal
缓拉全貌 · P0 · 从局部细节拉远揭示规模。见 references/cards/slow-pull-reveal.md。
- 一句话：起手 scale 1.25 + 偏移把兴趣点顶到画心（此时看不见全貌），8~15s 匀速拉远回正到素材原样满画幅
- spec：origin 固定**画心**（不是兴趣点——终点要零偏移回正），兴趣点靠位移顶到画心；缩放与位移**同一时间轴**；`camEase(0.55)` 比推镜更收住；hold 期按末速走完余量、正好停在原样
- pitfalls：拉到 scale<1（露出素材外空白，一眼假）；origin 照搬推镜咬兴趣点（收尾无法回正）；起手咬太松（1.05，全貌已在，白揭示）；缩放与位移拆两段（读作先缩再平移）；语义反了（该聚焦时用了拉远）
- tech：三条同轴 `interpolate`（scale + x + y）；**Ken Burns 拉镜半边**；语义方向与 slow-push-in 互为反面，一段只能选一个

### tilt-3d-page
3D 立面展示 · P1 · 把页面从"信息"变成"物件"。见 references/cards/tilt-3d-page.md。
- 一句话：正视静置一拍 → 1.2~1.8s 倾斜成 3D 立面（perspective 1000px + rotateY 12~25° 配 rotateX ~4.5° + scale 0.94 后退）→ 立面 hold 微透视慢漂
- spec：三层结构（父容器 perspective / 相机层 preserve-3d / 独立投影层 translateZ(-34px)+blur）；立起段**允许 power2.out**（是"摆放"事件不是持续运镜）；投影与立起同时长同缓动：浓度 0.05→0.19 + 往倾斜反侧挪；hold 期**两轴不同步**慢漂（一进一退）
- pitfalls：超过 30° 远端正文不可读；perspective <600 读作鱼眼变形；perspective 写在被 transform 的元素自己身上（透视中心不一致，多元素空间会散）；忘了 preserve-3d（translateZ 全失效，厚度感归零，最难查）；忘了 backface-visibility:hidden（边缘发灰）；投影不跟着变（页面读作贴纸）；hold 两轴同相位（机械转台）；倾斜后忘配 scale 后退（顶到画幅边）
- tech：`rotateY/rotateX/scale` 三条 interpolate + 独立投影 div；AE 的 3D 图层 `Y Rotation` + Camera，即素材站的 **3D mockup / device tilt** 品类

### sway-parallax
左右摇移 · P1 · 素材比画幅宽得多时。见 references/cards/sway-parallax.md。
- 一句话：镜头在一张宽近两倍画幅的长页面前横向匀速扫过（≤190px/s@960 宽），极轻 rotateY 3~4° 跟随
- spec：页面必须**真的**比画幅宽 1.5~2 倍（前提，不宽就没有可摇的）；三段速度曲线——`sine.in` 缓入 0.55s（**缓入距离按 `v×t/2` 换算才能与匀速段无阶跃地接上**，这是本卡时序的技术本体）→ 匀速扫过 → `camEase(0.5)` 极缓收住；`rotateY` 与 x 同轴，作用是把"图片在滑"改写为"镜头在页面前走"；`时长 = 行程 ÷ 速度`，**先定速度再算时长**
- pitfalls：超过 190px/s 观众扫读跟不上（唯一硬上限）；页面只宽 1.1 倍（读作画面抖了一下）；两端撞停；rotateY >8°（变成 3D 旋转卡）；缓入距离没按 v×t/2 换算（起步顿一下）；hold 期摇出素材右端露白；摇移方向逆着阅读方向；纵向长页误用本卡（那是 evidence-scroll-tour，它带减速停留语法）
- tech：x/rotateY/z 三条分段 interpolate；AE 的 Position X 关键帧或给 Camera 打关键帧（更接近物理）；**纵向变体**：x→y、rotateY→rotateX，参数与纪律不变

### orbit-drift
环绕微漂 · P1 · "镜头呼吸"的高级版，唯一可无限持续的运镜。见 references/cards/orbit-drift.md。
- 一句话：rotateY 与 rotateX 两条正弦**相位错开 90°** 合成闭合椭圆轨迹（±6°/±3.4°），叠前后呼吸与反向跟随投影，无始无终整段都是 hold
- spec：`rotateY = base + amp·sin(2πt/T)`、`rotateX = base + amp·sin(2π(t/T' + 0.25))` ← **0.25 = 90° 是"环绕"的唯一来源**（相位差 0 会退化成斜线＝摆动）；第三层 `z` 呼吸相位再错开；投影**反向**跟随；perspective 900px（比立面卡更近，位移差才读得出）；**周期策略是核心落地决定**——短用/需无缝循环用三轴同周期（轨迹严格闭合），长用（>2 圈）把 `periodXRatio` 设 0.75~0.8 让椭圆进动
- pitfalls：相位差给 0 或 180°（退化成摆动）；幅度 >10°（成了 3D 旋转秀的劣化版）；长时段用同周期（第三圈就被认出轨道，读作电动转台）；反之需无缝循环时用了不可通约周期（循环点跳帧）；周期 <5s 一圈（读作页面在晃、观众会晕——要更明显该加幅度不是提速）；perspective >1400（位移差看不出，白做）；投影同向跟随（物理不可能）；忘了 preserve-3d；用 Math.random 加噪声（本库不做沸腾/定格抖动，且破坏 seek 一致性）；拿它当入场（它没有入场，姿态建立交给 tilt-3d-page）
- tech：**最适合 Remotion 的一张**——纯 `frame` 的三行三角函数，不需要 interpolate，天然 seek-safe；可整段并入全局系统 G3 当 hold 期底噪的 3D 版。AE 用 `Y/X Rotation` 表达式 `value + amp*Math.sin(time*2*Math.PI/T + Math.PI/2)`（那个 `+Math.PI/2` 就是 90° 相位差）

### stage-keyframe-tour ◇
长页兴趣点巡游 · P1 · 超出画幅的长东西"讲到哪儿镜头停到哪儿"。见 references/cards/stage-keyframe-tour.md。
- 一句话：一张超出画幅的长落地页躺在 3D 透视舞台上（perspective 900 + rotateX 14° + rotateY −20° + scale 0.86 + 接触阴影），相机沿一条多关键帧路径依次停靠 3 个兴趣点（每点 hold 0.8~1s）再拉开离场
- 定位：长页有两种讲法——**页面动**（页面自己往上滚、相机不动，那是 evidence-scroll-tour◆）和**相机动**（页面躺着不动、相机在它上面飞）。后者才是"巡游"：观众看到的不是一份在滚动的文档，而是一个躺在台上的实物被人拿着镜头挨个指点。差别在观感的主语——前者"网页在演示自己"，后者"我在带你看"，带着讲的段落必须用后者
- spec：三层结构（`.world` 的 `perspective: 900px` 装在父容器 → `.camera` 的 `preserve-3d` 是唯一被 transform 的元素 → `.page` 长页本体高度远超画幅）；**俯角是必须的**（长页只有带 `rotateX` 才读作"躺在台上"，纯 rotateY 读作"立着的墙"＝tilt-3d-page 的语义）；路径表 `moves` 一行一个关键帧 `{d, px, py, zoom, roll}`，**相邻同姿态即 hold**；段间固定 `cubic-bezier(0.16,1,0.3,1)` + 每段不同方向的 ±0.5~1° roll；以全貌收尾
- 命门：**每一段的 zoom 必须绕当前兴趣点发生**——把目标点算成像素设为 `transform-origin` 再平移到画心。偷懒用固定原点 + 位移去凑，缩放会绕 2200px 长页的几何中心放大，镜头在 zoom 变化时同时甩出一段没人要的横向漂移（观感是"镜头在找东西"而不是"已经知道要看哪儿"）——这一条是本卡与"把长图放大再平移"的全部区别
- pitfalls：hold 不是真静止（信息量在 hold 里，段与段之间不留 hold 观众读不完任何一处）；兴趣点排序不单调；兴趣点超过 4 个（观众记不住）；`will-change` 提到相机层（只提文字容器）；竖向长距离用单条 EXPO（中段快到糊——换 remocn 的 smooth-descent 三段方案）

### cursor-locked-zoom ◇
光标锁定跟拍 · P1 · 小屏念长命令的唯一解法。见 references/cards/cursor-locked-zoom.md。
- 一句话：一条长命令在灰阶终端窗里逐字打出，相机 2.6~2.8x 锁死在光标上跟拍，字符从画面右侧被"喂"进来、光标恒在正中；打完停 0.75s 让人读完，再用 0.8s inOut 把 zoom 拉回 1 收在全景居中
- 定位：小屏念长命令是口播的真实死角（铺满竖屏则字号勉强可辨读不清，放大到能读则一屏装不下）。本卡的解法是**不要让观众读完整条，让他们跟着写的人往前走**——任何时刻画面里只有当前正在打的七八个字符，而它们大到不可能看不清
- spec：两层结构（`.camera` 是世界坐标层、`transform-origin: 0 0`，素材在世界坐标里位置固定）；**核心反解一行就是全部**——`tx = W/2 − zoom·cursorX`、`ty = H/2 − zoom·cursorY`（含义是"把锚点的缩放后位置搬到画面正中"）；锚点由"已揭示字符数 × 字宽（fontSize × 0.6）"算出，**等宽字体是硬约束**；可视矩形关在素材四边内做边界钳制（于是只 tween zoom 一个值、位移由钳制自动跟出）；打字段 `ease: none`
- 命门：**镜头由内容进度驱动而非独立关键帧**——它每帧由"已揭示了多少字符"算出来，没有自己的时间轴。所以打字快镜头就快、打字停镜头就停，两者不可能失步；若给镜头单独排一条位移 tween 去"追"打字，任何速率改动都会让它们错开，观感立刻塌成"放大的终端在播打字动画"
- pitfalls：漏掉 `transform-origin: 0 0`（默认 center 让 scale 绕元素中心发生，反解式子整个不成立——移植时最容易漏的一行）；不以全景收尾（观众眼里只有片段，需要一眼看到整条命令长什么样，不收这一拍等于没讲完）；换字体不实测 `charW`
- 与相邻卡的边界：stage-keyframe-tour◇ 停靠的是**预设**兴趣点（位置在动画前已知），本卡的目标位置**只有运行时才知道**；素材侧 terminal-typing-log◇ 是终端逐行推进（镜头不动、内容在动），本卡是单行长命令 + 镜头在动——两张可以接起来用（先跟拍念完命令，拉回全景后切给逐行日志跑起来）

### pip-zoom-box ◈
画中画放大 · P1 · 本类唯一**保留全景**的一张（局部长期驻留侧边）。见 references/cards/pip-zoom-box.md。
- 一句话：细描边取景框先在人物脸上出现停一拍，然后带着框里的画面 0.5s 平移放大到右侧空位定居，落位那刻换成白边卡 + 唯一投影，箭头随后从人物划向它
- 命门：框移动时**内容要跟着走**（框与内容同一个变换组，否则读作"空框飞过去"）；放大倍数写成 CONFIG 常量（典型 2.2x）
- 与本类其余七张的分界是**动的是不是画幅**：那七张相机一动全画幅都变，本卡只把一小块搬到旁边、全景一直在——所以它能在"后半程还要继续讲全景"的段落里长期驻留
- 与 magnifier-detail 的分工：那张是截图上弹出的圆形放大镜（用完即走），本卡是长期驻留的画中画卡

## 实战卡（项目沉淀，详情见各卡文件）

### pencil-sketch-draw ★
铅笔手绘揭示 · P1——铅笔骑在 SVG 路径笔尖当场画图，画完干净静置。来自 ann_nnng 手绘卡片技法复刻。代码 template/components/pencil.tsx。

### 运动承接转场六式 ★（六张卡，共享同一套纪律与同一份代码）
六式同属"动量交接"家族：相邻 Sequence 交叠 12~16 帧，`ShotFade` 只管像素淡化，方向与加速度全在两侧相机曲线里；
**两侧必须同向**（方向断裂比硬切更糟），**一个边界只用一式**。来自 ai-math-video 全片实战，
代码同为 template/motion-systems/transitions.tsx（CamKey 生成器 + 叠加层）。

### push-through-transition ★
推穿转场 · P0——出场加速推到 1.35x + 升 blur，入场从模糊的 1.16 高位反向沉降。家族基准式（无叠加层、只有 scale 轴），最安全、可反复用。生成器 pushThroughOut + settleIn。

### overexpose-flip-transition ★
过曝翻页转场 · P0——推向证据物至 1.5x + 重音层以切点为锚冲顶（切前 0.26s 升 / 切后 0.42s 落），入场从亮心拉出。**重音极性随底色换**：深底白色径向过曝 0.42~0.55，白底改压暗一拍。生成器 blowoutOut + settleIn(from 1.3) + Overexpose。

### whip-pan-transition ★
横甩转场 · P0——出场沿横轴甩出 + 8px 方向模糊 + 1.4° 微旋，入场从**同方向对侧**滑回、0.35s 刹住 + 二段回稳只收旋转。处理并列关系；交叠最短（≈9 帧，糊帧本身是遮挡）。生成器 whipOut/whipIn（两侧同 dir）。

### black-slam-transition ★
黑震切转场 · P0——出场相机定格一拍（全片唯一静止）+ 重音冲顶 + 最后 1 帧 hardOut 零交叠，入场满亮直切且开场自带运动（三段递减震位 + 从 1.10 后拉刹住）。**全片唯一硬切，限用一次**，留给最大反转。无生成器（出场是"不加键"）。

### pullback-cool-transition ★
后拉冷却转场 · P0——出场相机收住、内容自己沉暗失焦交出画面；入场是全片唯一 scale<1 起步的后拉（0.90→0.99，settle 0.90s 最慢，交叠 16 帧最长）。全 sine 系缓动的呼吸质感，用在情绪收束点。生成器 pullBackIn。

### particle-weld-transition ★
粒子溶接转场 · P0——出场主体碎成粒子向上飘散，入场用**同 seed** 的同一批粒子从下方继续上升、在新主体位置收拢，主体滞后 0.30s 成形。唯一动量在物质而非相机上的一式；语义必须真的是"同一件东西换形态"。组件 Shatter + 两侧同 seed ParticleDrift。

### long-take-world ★
长镜头世界画布 · P1——内容钉在世界坐标，一台相机随讲述连续运镜，useArrive 让内容在镜头到达前成形。代码 template/motion-systems/longtake.tsx（已实战：deepseek-harness-v2 V3 幕）。

## 真实视频挖掘卡（第三批◆，详情见各卡文件）

来源：小Lin说·韩股崩盘（douyin 362s）+ TheAIScaler shorts 播放量 top10。两频道语言差异值得按调性选卡——
**TheAIScaler** = 硬切 + 高饱和纯色底 + 字体对比的高频节拍（平均 1.5~3s 一个视觉事件），信息靠节奏压强；
**小Lin说** = 图表推演 + 聚焦压暗 + 长页证据的推理链，信息靠空间与因果。

- type-contrast-emphasis◆ · 字体对比重音 · P0 · 字幕花字——重音词换衬线斜体放大 1.5~2 倍（或换唯一强调色），强调靠字形气质落差而非弹跳；与 keyword-pop-highlight 同句互斥。
- focus-dim-spotlight◆ · 聚焦压暗切换 · P0 · 强调标注——讲到哪里哪里亮：目标保持原亮并点亮发光描边，其余压暗 40% 或整页高斯模糊，焦点随口播 0.2s 跳转。
- line-chart-story-draw◆ · 折线分段推演 · P0 · 数据信息图——折线不一次画完：新线段从拐点向右生长、标签段完成即弹出，对比虚线从同一拐点岔出第二种未来。
- ui-prop-theater◆ · 界面道具剧场 · P1 · 数据信息图——拟物 UI 道具（进度条/清单/滑杆）的状态按语音节拍分段跳进，界面自己演戏而不是跑 loading。
- cursor-actor-demo◆ · 光标演员演示 · P0 · 素材呈现——超大系统光标在 UI 截图上移动-悬停-点击，元素即时响应，一个动作对齐一个口播词。
- evidence-scroll-tour◆ · 证据长页慢滚 · P0 · 素材呈现——长截图页作为唯一动元素匀速上滚，预标注随页滚动，讲到关键处减速停留，滚速就是讲述节奏。
- motion-blur-slam-in◆ · 模糊甩入急停 · P1 · 素材呈现——素材卡带方向运动模糊从屏外高速飞入、0.2s 内急停落位，模糊由重到清收敛；与 media-pop-in 的 scale 弹跳二选一。
- color-slam-beat-card◆ · 纯色硬切节拍卡 · P0 · 转场结构——一帧硬切到高饱和纯色底（零过渡零擦除），色块上大字与素材卡错峰入场，停 1.5~5s 再硬切回，用底色跳变当节拍器。
- host-shrink-to-chip◆ · 人物缩位让台 · P1 · 人物互动——图形上台时讲者从全屏 0.4s 缩进角落圆形头像章继续口播，图形讲完再放大回全屏，主角让位但人不消失。
