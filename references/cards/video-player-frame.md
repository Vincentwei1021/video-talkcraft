类别: 素材呈现

## 输入类型
| 口播视频 | B-roll 视频 | 图片 |
|---|---|---|
| 可（引用别人的口播 / 采访片段——"他是这么说的"，播放器框就是引号）；本片主播自己的画面不进框 | **默认输入**（录屏 / 实拍单条当主体） | 不适用（静图装进播放器是假的——进度条在走画面却不动；图用 media-pop-in / slow-push-in） |

命门是**框里的是一段在放的视频**：进度条、时间码、播放键都在说"这是录像不是截图"，所以内容必须真的动。

## 常用场景
1. 产品 / AI 生成结果的录屏当证据（demo 演的：一段打字录屏 + 「录屏 · 案例 01」+ 来源 pill）
2. 教程里"看我操作一遍"的桌面录屏（`chrome: "browser"` 变体：顶部三点 + 地址栏）
3. 引用别人的视频 / 采访片段（标题 chip 写出处，来源 pill 写平台）
4. 单条 B-roll 撑一整句而画面里没有别的主体（不裸贴满幅，给它一个"物"）

## 意图
单视频镜头最常见的两种做法都弱：**裸贴满幅**——观众分不清这是本片画面还是引用的素材，也没有任何"物"可看；
**裸放一张白卡**——像贴了一张会动的照片，没有"正在播放"的语法。
播放器框把视频变成一个**有身份的物件**：标题说它是什么、来源说它从哪来、进度条说它多长放到哪、播放键说"现在开始"。
这四件事让一段素材从"画面"变成"证据"，也让整镜有了除视频以外的第二层可看的东西（参考 2026-09-07 用户反馈：
纯视频 / 纯文字镜"只有一个东西在动，太单调"）。

做对的命门：
1. **进度条 = 真实播放进度**（与视频同一个时间源；成片里按 `startFrom + 已播帧` 算）。装饰性匀速条一旦和画面里的动作对不上，观众立刻知道这是假播放器。
2. **先按键、再起步**：播放键 punch（1.15→1，0.2s）与进度起步同帧，键先于进度是"播放器"的语法；反过来（条先走键后换）读作 GIF。
3. **框是容器、条是控件，两者不同帧**：条比框晚 0.15s 滑上、退场先 0.2s 收——同进同出就成了一张贴图。
4. **视频画面本身不做滤镜 / 缩放 / 淡入淡出动画**：画面的活由整框极缓推 1→1.03 负责（G1 相机）；给视频加特效等于承认视频不够看。

## 动效核心
- 层级（下→上）：白底 → 框（白边 8 + hairline 1px + 唯一投影 `0 12px 60px rgba(0,0,0,.22)`，圆角 16）→ 视频（`object-fit: cover`，圆角 8）→ 标题 chip（左上）+ 来源 pill（右上）→ 播放条（底部 56px 渐变 scrim）。
- **框落位**：opacity 0→1 + scale .96→1 + y 16→0，0.5s `power3.out`；落位后 scale 1→1.03 匀速推到退场（linear，末速非零）。
- **播放条 / chip / pill**：+0.15s 起 opacity 0→1 + y ±12→0，0.35s `power3.out`（条从下上来，chip / pill 从上下来）。
- **按下播放**（`playAt` 0.5s）：键从 ▶ 换成 ❚❚，scale 1.15→1 0.2s `back.out(1.7)`；同帧 `played = t − playAt` 起步。
- **进度**：`progress = played / clipSec`，已播条宽 + 圆钮位置 + 时间码 `mm:ss / mm:ss`（等宽数字）全由同一个 `played` 推出；章节刻度（`markers` 比例）在 `progress ≥ m` 时由白 30% 变 100%。
- **退场**：`exitAt` 条 / chip / pill 0.2s 淡出 → +0.2s 框 scale→.98 + 淡出 0.35s `power2.in`；视频在框收完那帧停。
- **browser 变体**：顶部 36px 浅灰条（三点 + 白色地址栏 pill 写来源域名），视频区圆角只留下方；其余节拍相同。

## 参数表
| 参数 | 典型值 | 调节手感 |
|------|--------|----------|
| `frameIn` | 0.5s | <0.3 像弹窗；>0.7 观众等框等到不耐烦 |
| `chromeDelay` | 0.15s | 0 = 框条同帧成贴图；>0.3 条像迟到的字幕 |
| `playAt` | 0.5s | 与框落位同刻最顺（落位即按下）；晚于 1.0 观众会问"怎么不放" |
| `clipSec` | 真实片长 | 填错时间码就撒谎——成片按素材 ffprobe 时长填，不按镜头长 |
| `markers` | [0.35, 0.72] | 章节刻度给"这段里有几个看点"的暗示；>4 个像刻度尺，0 个也行 |
| `push` | 1.03 | 镜头 >10s 可到 1.05；>1.06 框边会逼近安全区 |
| `barH` | 56 | 条越高 scrim 越重；<44 播放键会顶到边 |
| `exitAt` / `exit` | 7.6 / 0.35 | 条与框的 0.2s 错峰是命门③，别合并 |
| `chrome` | `player` / `browser` | 网页录屏用 browser；手机竖屏录屏用 player 并把框改 9:16（宽 243 高 432） |

## 已知坑
- 进度条匀速跑满整镜、与素材真实时长无关——观众拿它对画面动作，一对不上就知道是装饰，比没有更假。
- 视频里再套一层淡入 / Ken Burns——框已经在极缓推，画面再动就是双重运动；且"给视频加特效"读作视频不够看。
- 播放键一直是 ▶——在播却显示"播放"，播放器语法反了；或者键换了进度没动，读作卡住。
- 框贴到画幅边或压进字幕带——播放器是证据卡，走 action-safe 96；框底边留 ≥60px 给字幕（layout.md §9）。
- 用截图（静图）冒充录屏放进框——进度在走画面不动，一眼假；静图请回 media-pop-in。
- 时间码用比例字体——数字跳动时宽度抖，等宽 / `tabular-nums` 是播放器的常识。

## 动效范围
- 属于本卡的：框 0.5s 落位（opacity + scale .96→1 + y 16→0）与整框极缓推 1→1.03；播放条 / chip / pill 晚 0.15s 滑上、退场先 0.2s 收；播放键按下 punch（1.15→1，back.out）与进度同帧起步；进度条 / 圆钮 / 时间码 / 章节刻度由同一个 `played` 推出；退场条先框后。
- 不属于本卡的：示意视频（demos/_lib/media/v-typing.webm）、chip / pill 的具体文案、白边卡的具体色值与投影参数、浅底舞台。
- 迁移接口：**皮按风格档蒙**（design-language §0.4）——浅底 = 白边卡 + hairline + 唯一投影（demo）；深底 = 深 tile + 亮 hairline、scrim 换 rgba(0,0,0,.7)；已播条与刻度点亮色换本片 accent，时间码字体换本片数字字体；框尺寸按镜头素材比例（16:9 / 9:16 / 4:3）与主列宽（≤1440@1080p）；`clipSec` 按素材真实时长。
- 底色要求：白底即可（框自带投影分层）；深底版把框底换深 tile，白边换 1px 亮 hairline。

## 落位自检（选卡时抄进 SHOTBOOK 该镜自检列）
- 框四边在 action-safe（96@1080p）内；框底边到字幕带顶 ≥60px；框与同屏其他主体包围盒不相交。
- `clipSec` = ffprobe 素材时长；`startFrom` 与口播锚点对齐（"看这里"说出口时画面里正是那一秒）。
- 播放键 punch 帧 = 进度起步帧（同一 `playAt`）；退场条比框早 0.2s（抽两帧核）。
- 视频层没有任何 filter / 二次 transform；整框推 ≤1.05。
- 单视频镜必须用它或它的变体（SKILL.md ③「单视频镜头要有播放器」），裸贴满幅只允许当底床（不是主体）。
